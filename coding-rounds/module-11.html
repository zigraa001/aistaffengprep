1. Monotonic Stack (The Most Important Pattern)

Core Idea & Template ▼

A monotonic stack maintains elements in sorted order (either increasing or decreasing) from bottom to top. When a new element violates the order, we pop elements and process them. This lets us find the next greater, next smaller, previous greater, or previous smaller element for every position in O(n) total time.

Why O(n)? Each element is pushed at most once and popped at most once, so across all iterations the total work is 2n = O(n).

Template: Next Greater Element (Python)

def next_greater(nums):
    """For each element, find the next element that is strictly greater."""
    n = len(nums)
    result = [-1] * n
    stack = []  # stores indices, monotonic decreasing values

    for i in range(n):
        # Pop everything smaller than nums[i]
        while stack and nums[stack[-1]] < nums[i]:
            idx = stack.pop()
            result[idx] = nums[i]
        stack.append(i)

    return result

# Example: nums = [2, 1, 2, 4, 3]
# result =        [4, 2, 4,-1,-1]

Template: Next Greater Element (Java)

import java.util.Arrays;
import java.util.ArrayDeque;
import java.util.Deque;

public int[] nextGreater(int[] nums) {
    int n = nums.length;
    int[] result = new int[n];
    Arrays.fill(result, -1);
    // ArrayDeque as a stack — stores indices; values are monotonically decreasing
    Deque<Integer> stack = new ArrayDeque<>();

    for (int i = 0; i < n; i++) {
        while (!stack.isEmpty() && nums[stack.peek()] < nums[i]) {
            int idx = stack.pop();
            result[idx] = nums[i];
        }
        stack.push(i);
    }
    return result;
}
// Example: nums = [2, 1, 2, 4, 3]
// result =        [4, 2, 4,-1,-1]

Key insight: The stack stores indices (not values) so we can write answers back to the correct position. The stack's values are monotonically decreasing: when we encounter a larger element, everything smaller gets its answer.

Why O(n)? — Amortized Analysis Deep Dive ▼

A common interview follow-up: "The inner while loop can execute multiple times. Isn't this O(n²)?" Here is the formal amortized argument.

Claim: The total number of push + pop operations across the entire loop is at most 2n.

Proof by accounting:

1. Each element nums[i] is pushed onto the stack exactly once (line: stack.append(i)).

2. Each element can be popped at most once — once it is removed it is never pushed again.

3. Therefore: total pushes ≤ n, total pops ≤ n, total operations ≤ 2n.

4. Amortized cost per iteration = 2n / n = O(1). The loop body is O(1) amortized, making the full algorithm O(n).

Potential function view (for the curious): Assign a "credit" of 2 to each element when it is pushed. One credit pays for the push; the other is held in reserve. When the element is later popped, it uses its reserve credit. Since every element was given exactly 2 credits, total cost = 2n credits used = O(n).

What this means in an interview: Don't be intimidated by the nested loop. Prove it by saying: "Each element is pushed once and popped at most once, giving at most 2n total stack operations regardless of the number of loop iterations." Interviewers at FAANG will expect you to state this unprompted for Hard-difficulty monotonic stack problems.

LC 739: Daily Temperatures ▼

Problem: Given daily temperatures, return how many days until a warmer day. This is exactly "next greater element" but returning the distance instead of the value.

def dailyTemperatures(temperatures):
    n = len(temperatures)
    answer = [0] * n
    stack = []  # indices, monotonic decreasing temps

    for i in range(n):
        while stack and temperatures[stack[-1]] < temperatures[i]:
            idx = stack.pop()
            answer[idx] = i - idx  # distance, not value
        stack.append(i)

    return answer

Java

import java.util.ArrayDeque;
import java.util.Deque;

public int[] dailyTemperatures(int[] temperatures) {
    int n = temperatures.length;
    int[] answer = new int[n];           // default 0
    Deque<Integer> stack = new ArrayDeque<>(); // indices

    for (int i = 0; i < n; i++) {
        while (!stack.isEmpty() && temperatures[stack.peek()] < temperatures[i]) {
            int idx = stack.pop();
            answer[idx] = i - idx;       // days until warmer
        }
        stack.push(i);
    }
    return answer;
}
LC 84: Largest Rectangle in Histogram (Hard) ▼

Why this matters: This is one of the most-asked hard stack problems. It combines "previous smaller" and "next smaller" into a single pass. For each bar, we need to know how far left and right it can extend as the shortest bar.

def largestRectangleArea(heights):
    stack = []  # indices, monotonic increasing heights
    max_area = 0
    heights.append(0)  # sentinel to flush remaining bars

    for i, h in enumerate(heights):
        # When we see a shorter bar, pop and compute areas
        while stack and heights[stack[-1]] > h:
            height = heights[stack.pop()]
            # Width: from current stack top (prev smaller) to i
            width = i if not stack else i - stack[-1] - 1
            max_area = max(max_area, height * width)
        stack.append(i)

    heights.pop()  # clean up sentinel
    return max_area

Key insight: When we pop index j, the current i is the next smaller to the right, and stack[-1] after popping is the previous smaller to the left. The width of the rectangle with height heights[j] is i - stack[-1] - 1.

Java

import java.util.ArrayDeque;
import java.util.Deque;

public int largestRectangleArea(int[] heights) {
    Deque<Integer> stack = new ArrayDeque<>();
    int maxArea = 0;
    // Append a sentinel 0 logically by extending the loop to n
    for (int i = 0; i <= heights.length; i++) {
        int h = (i == heights.length) ? 0 : heights[i];
        while (!stack.isEmpty() && heights[stack.peek()] > h) {
            int height = heights[stack.pop()];
            int width = stack.isEmpty() ? i : i - stack.peek() - 1;
            maxArea = Math.max(maxArea, height * width);
        }
        stack.push(i);
    }
    return maxArea;
}

2. Parenthesis Problems

LC 20: Valid Parentheses ▼

The foundational stack problem. Push opening brackets; on a closing bracket, check the top matches. Two edge cases: stack empty on close (extra closer), stack non-empty at end (extra opener).

def isValid(s):
    stack = []
    match = {')': '(', ']': '[', '}': '{'}

    for ch in s:
        if ch in match:
            if not stack or stack[-1] != match[ch]:
                return False
            stack.pop()
        else:
            stack.append(ch)

    return len(stack) == 0

Java

import java.util.ArrayDeque;
import java.util.Deque;
import java.util.Map;

public boolean isValid(String s) {
    Deque<Character> stack = new ArrayDeque<>();
    Map<Character, Character> match = Map.of(')', '(', ']', '[', '}', '{');

    for (char ch : s.toCharArray()) {
        if (match.containsKey(ch)) {
            if (stack.isEmpty() || stack.peek() != match.get(ch)) return false;
            stack.pop();
        } else {
            stack.push(ch);
        }
    }
    return stack.isEmpty();
}
LC 22: Generate Parentheses & LC 1249: Minimum Remove ▼

Generate Parentheses (Backtracking + Stack invariant)

Generate all valid combinations of n pairs. The key constraint: at any point, open_count ≥ close_count.

def generateParenthesis(n):
    result = []

    def backtrack(current, open_count, close_count):
        if len(current) == 2 * n:
            result.append(current)
            return
        if open_count < n:
            backtrack(current + '(', open_count + 1, close_count)
        if close_count < open_count:
            backtrack(current + ')', open_count, close_count + 1)

    backtrack('', 0, 0)
    return result

Generate Parentheses (Java)

import java.util.ArrayList;
import java.util.List;

public List<String> generateParenthesis(int n) {
    List<String> result = new ArrayList<>();
    backtrack(result, new StringBuilder(), 0, 0, n);
    return result;
}

private void backtrack(List<String> result, StringBuilder current,
                        int open, int close, int n) {
    if (current.length() == 2 * n) {
        result.add(current.toString());
        return;
    }
    if (open < n) {
        current.append('(');
        backtrack(result, current, open + 1, close, n);
        current.deleteCharAt(current.length() - 1);
    }
    if (close < open) {
        current.append(')');
        backtrack(result, current, open, close + 1, n);
        current.deleteCharAt(current.length() - 1);
    }
}

Minimum Remove to Make Valid (LC 1249)

Use a stack to track indices of unmatched parentheses, then rebuild the string without them.

def minRemoveToMakeValid(s):
    indices_to_remove = set()
    stack = []  # indices of unmatched '('

    for i, ch in enumerate(s):
        if ch == '(':
            stack.append(i)
        elif ch == ')':
            if stack:
                stack.pop()  # matched
            else:
                indices_to_remove.add(i)  # unmatched ')'

    indices_to_remove.update(stack)  # remaining unmatched '('
    return ''.join(ch for i, ch in enumerate(s) if i not in indices_to_remove)

Minimum Remove to Make Valid (Java)

import java.util.ArrayDeque;
import java.util.Deque;
import java.util.HashSet;
import java.util.Set;

public String minRemoveToMakeValid(String s) {
    Set<Integer> toRemove = new HashSet<>();
    Deque<Integer> stack = new ArrayDeque<>(); // unmatched '(' indices

    for (int i = 0; i < s.length(); i++) {
        char ch = s.charAt(i);
        if (ch == '(') {
            stack.push(i);
        } else if (ch == ')') {
            if (!stack.isEmpty()) {
                stack.pop();           // matched pair
            } else {
                toRemove.add(i);       // unmatched ')'
            }
        }
    }
    // remaining stack entries are unmatched '('
    while (!stack.isEmpty()) toRemove.add(stack.pop());

    StringBuilder sb = new StringBuilder();
    for (int i = 0; i < s.length(); i++) {
        if (!toRemove.contains(i)) sb.append(s.charAt(i));
    }
    return sb.toString();
}

3. Expression Evaluation

How Operator Precedence Works — "3 + 2 * 4" Step-by-Step ▼

Before diving into code, understand what a stack-based evaluator must do when operator precedence is in play (relevant for LC 227: Basic Calculator II). The algorithm: when we see an operator, peek at the operator on the stack. If the stack operator has higher or equal precedence, pop and evaluate first.

Expression: 3 + 2 * 4 → expected result: 11

StepTokenActionOperand StackOperator StackNotes
1 3 Push operand [3] [] Numbers always go on the operand stack
2 + Stack empty, push operator [3] [+] Nothing to compare against yet
3 2 Push operand [3, 2] [+]
4 * Peek: + has lower precedence than * → push * [3, 2] [+, *] Do not yet evaluate +
5 4 Push operand [3, 2, 4] [+, *]
6 EOL Drain stacks: pop *, pop 4 and 2, compute 2*4=8, push 8 [3, 8] [+] Higher-precedence operator evaluated first
7 EOL Pop +, pop 8 and 3, compute 3+8=11, push 11 [11] [] Final answer: 11

Key takeaway: LC 224 (Basic Calculator with parentheses) uses a sign-folding trick instead of explicit precedence tracking because it only involves + and -, which have equal precedence. LC 227 (with * and /) requires the comparison above.

LC 150: Reverse Polish Notation & LC 224: Basic Calculator ▼

Reverse Polish Notation (Python)

RPN eliminates the need for parentheses and operator precedence. Operands go on the stack; operators pop two operands and push the result.

def evalRPN(tokens):
    stack = []
    ops = {
        '+': lambda a, b: a + b,
        '-': lambda a, b: a - b,
        '*': lambda a, b: a * b,
        '/': lambda a, b: int(a / b),  # truncate toward zero
    }

    for token in tokens:
        if token in ops:
            b, a = stack.pop(), stack.pop()  # note order!
            stack.append(ops[token](a, b))
        else:
            stack.append(int(token))

    return stack[0]

Reverse Polish Notation (Java)

import java.util.ArrayDeque;
import java.util.Deque;
import java.util.Set;

public int evalRPN(String[] tokens) {
    Deque<Integer> stack = new ArrayDeque<>();
    Set<String> ops = Set.of("+", "-", "*", "/");

    for (String token : tokens) {
        if (ops.contains(token)) {
            int b = stack.pop();  // second operand
            int a = stack.pop();  // first operand — order matters for - and /
            int result = switch (token) {
                case "+" -> a + b;
                case "-" -> a - b;
                case "*" -> a * b;
                default  -> (int)(a / (double) b);  // truncate toward zero
            };
            stack.push(result);
        } else {
            stack.push(Integer.parseInt(token));
        }
    }
    return stack.pop();
}

Basic Calculator (LC 224) — handles +, -, (, ) (Python)

The trick: use a sign stack. When we enter parentheses, push the current sign. When we hit ), pop it. This avoids needing to recursively evaluate sub-expressions.

def calculate(s):
    stack = [1]  # sign stack; 1 = positive context
    result = 0
    num = 0
    sign = 1

    for ch in s:
        if ch.isdigit():
            num = num * 10 + int(ch)
        elif ch in '+-':
            result += sign * num
            num = 0
            sign = stack[-1] * (1 if ch == '+' else -1)
        elif ch == '(':
            stack.append(sign)
        elif ch == ')':
            result += sign * num
            num = 0
            stack.pop()

    return result + sign * num

Basic Calculator (Java)

import java.util.ArrayDeque;
import java.util.Deque;

public int calculate(String s) {
    Deque<Integer> stack = new ArrayDeque<>();
    stack.push(1);          // initial positive context
    int result = 0, num = 0, sign = 1;

    for (char ch : s.toCharArray()) {
        if (Character.isDigit(ch)) {
            num = num * 10 + (ch - '0');
        } else if (ch == '+' || ch == '-') {
            result += sign * num;
            num = 0;
            sign = stack.peek() * (ch == '+' ? 1 : -1);
        } else if (ch == '(') {
            stack.push(sign);   // save sign context before entering parens
        } else if (ch == ')') {
            result += sign * num;
            num = 0;
            stack.pop();        // restore outer sign context
        }
        // spaces are ignored
    }
    return result + sign * num;
}

4. Monotonic Deque: Sliding Window Maximum

LC 239: Sliding Window Maximum ▼

Problem: Given an array and window size k, return the max of each window. Brute force is O(nk). A monotonic deque solves it in O(n).

Why a deque? We need to pop from both ends: from the back (to maintain decreasing order) and from the front (to evict elements outside the window).

from collections import deque

def maxSlidingWindow(nums, k):
    dq = deque()  # stores indices; values are monotonically decreasing
    result = []

    for i, num in enumerate(nums):
        # Remove elements outside the window
        while dq and dq[0] < i - k + 1:
            dq.popleft()

        # Maintain decreasing order: remove smaller elements from back
        while dq and nums[dq[-1]] <= num:
            dq.pop()

        dq.append(i)

        # Window is full; record the max (front of deque)
        if i >= k - 1:
            result.append(nums[dq[0]])

    return result

Java

import java.util.ArrayDeque;
import java.util.Deque;

public int[] maxSlidingWindow(int[] nums, int k) {
    int n = nums.length;
    int[] result = new int[n - k + 1];
    Deque<Integer> dq = new ArrayDeque<>(); // stores indices; decreasing values

    for (int i = 0; i < n; i++) {
        // Evict indices outside the current window
        while (!dq.isEmpty() && dq.peekFirst() < i - k + 1) {
            dq.pollFirst();
        }
        // Remove indices with smaller values from the back (they can never be max)
        while (!dq.isEmpty() && nums[dq.peekLast()] <= nums[i]) {
            dq.pollLast();
        }
        dq.offerLast(i);

        if (i >= k - 1) {
            result[i - k + 1] = nums[dq.peekFirst()];
        }
    }
    return result;
}

Interview tip: Interviewers often ask "why not a heap?" A max-heap gives O(n log k) because you cannot efficiently remove elements that leave the window. The deque avoids this by eagerly discarding elements that can never be the answer.

Deque vs Heap Trade-offs ▼

For Sliding Window Maximum (and related problems), two data structures are candidates. Here is why the deque wins:

PropertyMonotonic DequeMax-Heap (lazy deletion)
Time complexity O(n) total, amortized O(1)/element O(n log k) — each heap operation is O(log k)
Space complexity O(k) — deque holds at most k indices O(n) — stale entries accumulate until lazily removed
Eviction of expired elements O(1) — simply check front index O(log k) lazy pop on each query
Supports window minimum also? Yes — flip to increasing deque Need a separate min-heap; hard to do simultaneously
Implementation complexity Moderate — two-ended invariant to maintain Moderate — need to track "valid" vs "stale" entries
Works for arbitrary queries (not just adjacent windows)? No — must process left-to-right sequentially Yes — heap supports arbitrary queries

When to choose heap: If you need top-k elements from overlapping but non-sequential queries, or if window boundaries are not monotone (e.g., variable-length windows where you shrink from the left non-trivially), a heap with lazy deletion is more flexible, despite the O(log k) overhead.

5. Design Problems

LC 155: Min Stack & LC 232: Queue Using Two Stacks ▼

Min Stack — O(1) getMin (Python)

Keep a parallel stack that tracks the running minimum. Each entry in the min stack corresponds to "what is the minimum if the main stack has this many elements?"

class MinStack:
    def __init__(self):
        self.stack = []
        self.min_stack = []  # parallel; min_stack[i] = min of stack[0..i]

    def push(self, val):
        self.stack.append(val)
        min_val = min(val, self.min_stack[-1] if self.min_stack else val)
        self.min_stack.append(min_val)

    def pop(self):
        self.stack.pop()
        self.min_stack.pop()

    def top(self):
        return self.stack[-1]

    def getMin(self):
        return self.min_stack[-1]

Min Stack (Java)

import java.util.ArrayDeque;
import java.util.Deque;

class MinStack {
    private final Deque<Integer> stack    = new ArrayDeque<>();
    private final Deque<Integer> minStack = new ArrayDeque<>(); // parallel min tracker

    public void push(int val) {
        stack.push(val);
        int minVal = minStack.isEmpty() ? val : Math.min(val, minStack.peek());
        minStack.push(minVal);
    }

    public void pop() {
        stack.pop();
        minStack.pop();
    }

    public int top() {
        return stack.peek();
    }

    public int getMin() {
        return minStack.peek();
    }
}

Queue Using Two Stacks — Amortized O(1) (Python)

Why this works: Stack A (input) collects pushes. Stack B (output) serves pops. We only transfer A to B (reversing order) when B is empty. Each element is moved at most once, so amortized cost per operation is O(1).

class MyQueue:
    def __init__(self):
        self.stack_in = []   # push here
        self.stack_out = []  # pop from here

    def push(self, x):
        self.stack_in.append(x)

    def pop(self):
        self._transfer()
        return self.stack_out.pop()

    def peek(self):
        self._transfer()
        return self.stack_out[-1]

    def empty(self):
        return not self.stack_in and not self.stack_out

    def _transfer(self):
        if not self.stack_out:
            while self.stack_in:
                self.stack_out.append(self.stack_in.pop())

Queue Using Two Stacks (Java)

import java.util.ArrayDeque;
import java.util.Deque;

class MyQueue {
    private final Deque<Integer> stackIn  = new ArrayDeque<>();
    private final Deque<Integer> stackOut = new ArrayDeque<>();

    public void push(int x) {
        stackIn.push(x);
    }

    public int pop() {
        transfer();
        return stackOut.pop();
    }

    public int peek() {
        transfer();
        return stackOut.peek();
    }

    public boolean empty() {
        return stackIn.isEmpty() && stackOut.isEmpty();
    }

    // Transfer only when stackOut is exhausted — each element moves at most once
    private void transfer() {
        if (stackOut.isEmpty()) {
            while (!stackIn.isEmpty()) {
                stackOut.push(stackIn.pop());
            }
        }
    }
}

Real-world usage: This pattern appears in message queues where producers and consumers operate at different rates. Kafka's segment architecture is conceptually similar: writes go to the active segment, reads come from older sealed segments.

Real-World Stack/Queue Usage at Scale ▼

Understanding how stacks and queues appear in production systems helps you contextualise interview answers and gives you strong "why does this matter?" narrative.

1. Browser JavaScript Call Stack (V8 Engine)

V8, Chrome's JavaScript engine, maintains a call stack that is a literal hardware-aligned stack. Each function call pushes a stack frame containing: the return address, local variables, and the caller's frame pointer. The default stack size in Node.js is approximately ~15,000 frames (configurable via --stack-size). Exceeding this causes a RangeError: Maximum call stack size exceeded. This is why recursive algorithms that could be O(n) deep — e.g., naive tree DFS on a 100k-node linked list — need to be converted to iterative using an explicit stack. In performance-critical V8 code, engineers use trampolines or continuation-passing style to avoid deep stacks.

2. Undo/Redo in Editors — Command Pattern + Two Stacks

Every serious editor (VS Code, IntelliJ, Google Docs) uses two stacks for undo/redo. The key design is the Command Pattern: each user action is an object implementing execute() and undo(). On an action, push to the undo stack and clear the redo stack. On Ctrl-Z, pop from undo, call undo(), push to redo stack. On Ctrl-Y, reverse. VS Code's implementation (EditStack in editorUndoRedoService.ts) groups commands into "elements" with configurable time-based coalescing, but the underlying structure is two stacks. The undo stack is bounded (VS Code defaults to 1000 operations) to prevent unbounded memory growth — a real engineering trade-off.

3. Kafka Consumer Offset Management — Queue Semantics

Apache Kafka's consumer group model is a distributed queue abstraction. Each partition is an ordered log (queue). Consumers track their position via offsets — an integer pointer to the next message to consume. Committing an offset is analogous to "dequeuing". Kafka does not physically remove messages on consume; instead it advances the consumer's offset pointer and retains data for a configurable log.retention.ms. This enables "rewind" (set offset to an earlier position) and multi-consumer patterns (different consumer groups have independent offsets on the same partition). The compacted topic variant turns the queue into a key-value store with exactly-once semantics — relevant when you need idempotent state machines at scale (e.g., Flink checkpointing state into Kafka).

4. React Reconciliation — Stack-Based Fiber Traversal

React 16+ uses the Fiber architecture, which replaced the original synchronous recursive reconciler with an iterative, stack-based work loop. Before Fiber, reconciliation used the JavaScript call stack (recursive), which meant once started it could not be paused — causing dropped frames for large trees. Fiber assigns each React element a "fiber node" (a work unit) and maintains an explicit work-in-progress tree with a pointer to the next fiber to process. The scheduler uses a priority queue (min-heap by expiry time) to decide which fibers to process next, and the traversal itself uses a linked-list stack (child → sibling → return pointers). This lets React pause reconciliation mid-tree, yield to the browser, and resume — the essence of Concurrent Mode. The explicit stack replaces the implicit call stack, giving React full control over scheduling.

8. Interview Follow-Up Questions

Common Follow-Ups Interviewers Ask ▼

These questions are frequently used to probe depth after you code a correct solution. Prepare concise but substantive answers.

Q: Can you solve Trapping Rain Water with a stack? What about two pointers? Compare the approaches.

Both are O(n) time. The monotonic stack approach processes water in horizontal layers: pop when a taller bar is found, and calculate water trapped between the popped bar and the new bar. It's intuitive but uses O(n) space for the stack. The two-pointer approach uses O(1) space and is generally preferred: maintain left and right pointers, and track max_left / max_right. Move the pointer on the side with the smaller max — that side's trapped water is determined. The stack approach is easier to extend to variants (e.g., 2D Trapping Rain Water is solved by a min-heap, analogously).

Q: How would you extend MinStack to support O(1) getMax as well?

Add a second parallel stack max_stack that mirrors min_stack but tracks the running maximum. On push(val): max_stack.push(max(val, max_stack.top())). On pop(): pop both stacks. getMax() returns max_stack.top(). Both stacks remain synchronized with the main stack. Space doubles from O(n) to O(n) (same asymptotic class, just 3x the stacks). If memory is severely constrained, you can use a "store only on change" optimization: push to min/max stack only when the new value is a new extremum, and store (value, count) pairs. This reduces space for repetitive sequences.

Q: What if the sliding window needs both min AND max? Can you still do O(n)?

Yes. Maintain two monotonic deques simultaneously: one decreasing (for max) and one increasing (for min). Both are updated identically to the single-deque approach — add the new index, evict from the front if outside window, and maintain order from the back. Each deque operation is still O(1) amortized, so the combined algorithm is O(n). This is used in problems like "Longest Subarray with Bounded Max and Min" (LC 1438).

Q: How would you implement a thread-safe queue? What synchronization primitives would you use?

In Java: use java.util.concurrent.LinkedBlockingQueue (bounded) or ConcurrentLinkedQueue (unbounded, non-blocking). The blocking variant uses ReentrantLock with two Condition objects (notEmpty, notFull) — producer waits on notFull, consumer waits on notEmpty. The non-blocking variant uses CAS (Compare-And-Swap) on a tail pointer (Michael-Scott queue algorithm), avoiding lock overhead at the cost of ABA-problem complexity. In Python, queue.Queue uses a threading.Condition internally. In Go, a channel is a built-in thread-safe queue with configurable buffering. Key trade-off: blocking queues are simpler but can cause thread starvation under contention; lock-free queues scale better but are harder to implement correctly.

Q: In Largest Rectangle in Histogram, what happens if there are duplicate heights?

The algorithm still works correctly. When we use > (strictly greater) as the pop condition, duplicate heights are kept on the stack and only popped when a strictly smaller bar arrives. The final rectangle for duplicates will be computed when the last occurrence is popped — at that point the width spans all consecutive duplicates. If you use ≥, duplicates are popped earlier but the computation still yields the correct max area, because the width calculation i - stack[-1] - 1 adjusts accordingly. Both versions are correct; the > variant is slightly more intuitive.
