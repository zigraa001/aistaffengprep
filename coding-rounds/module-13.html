1. Bit Basics

Bitwise Operators & Binary Representation ▼

Every integer is stored as a sequence of bits. Understanding how operators manipulate these bits at the hardware level is the key to all bit manipulation problems.

Operator Truth Table

ABA & BA | BA ^ B~A
000001
010111
100110
111100

Shift Operators

  • Left shift (x << k): Multiplies x by 2k. Fills vacated bits with 0.
  • Right shift (x >> k): Divides x by 2k (floor). In most languages, arithmetic right shift preserves the sign bit for negative numbers; logical right shift (>>> in Java) fills with 0.

Two's Complement

Negative numbers use two's complement: to get -x, invert all bits of x and add 1. For a 32-bit integer, -1 is 1111...1111 (all 32 bits set). This means ~x == -x - 1, a relationship that shows up in many bit tricks.

Key insight: -n == ~n + 1. This means n & (-n) isolates the lowest set bit, because negation flips all bits above the lowest set bit and keeps it.

# Python — binary representation
# Python integers have arbitrary precision, so we mask to 32 bits for display
def show_bits(n, width=8):
    """Display the binary representation of n."""
    if n < 0:
        n = n & ((1 << width) - 1)  # two's complement mask
    return format(n, f'0{width}b')

print(show_bits(13))      # 00001101
print(show_bits(-13, 8))  # 11110011  (two's complement)
print(show_bits(13 << 2)) # 00110100  (13 * 4 = 52)
print(show_bits(13 >> 1)) # 00000110  (13 // 2 = 6)

// Java — binary representation
public class ShowBits {
    public static String showBits(int n) {
        // Integer.toBinaryString does not zero-pad or show two's complement
        // Use String.format with a mask for a consistent 8-bit display
        return String.format("%8s", Integer.toBinaryString(n & 0xFF))
                     .replace(' ', '0');
    }

    public static void main(String[] args) {
        System.out.println(showBits(13));       // 00001101
        System.out.println(showBits(-13));      // 11110011 (masked to 8 bits)
        System.out.println(showBits(13 << 2)); // 00110100
        System.out.println(showBits(13 >> 1)); // 00000110

        // Full 32-bit: Integer.toBinaryString(-13) shows all 32 bits
        System.out.println(Integer.toBinaryString(-13));
        // "11111111111111111111111111110011"

        // Arithmetic vs logical right shift
        int x = -8;
        System.out.println(x >> 1);   // -4  (arithmetic, sign preserved)
        System.out.println(x >>> 1);  // 2147483644 (logical, fills with 0)
    }
}

// C++ — binary representation
#include <cstdint>
#include <bitset>
#include <iostream>

void show_bits(int32_t n) {
    // std::bitset gives a clean 32-bit string
    std::cout << std::bitset<8>(n & 0xFF) << "\n";
}

int main() {
    show_bits(13);       // 00001101
    show_bits(-13);      // 11110011 (masked to 8 bits)
    show_bits(13 << 2); // 00110100

    // Note: right-shifting a negative signed int is implementation-defined
    // before C++20. Use unsigned types or cast for portability.
    uint32_t u = static_cast<uint32_t>(-13);
    std::cout << std::bitset<32>(u) << "\n"; // all 32 bits
}

2. Essential Bit Tricks

The Toolkit Every Engineer Needs ▼

Check if Power of 2

A power of 2 has exactly one bit set: 1, 10, 100, 1000... in binary. Subtracting 1 flips that bit and sets all lower bits: 0111.... So n & (n - 1) is zero if and only if n is a power of 2.

# Python
def is_power_of_two(n: int) -> bool:
    return n > 0 and (n & (n - 1)) == 0

# Example: 16 = 10000, 15 = 01111 -> 10000 & 01111 = 0  (True)
# Example: 18 = 10010, 17 = 10001 -> 10010 & 10001 = 10000 (False)

// Java
public boolean isPowerOfTwo(int n) {
    return n > 0 && (n & (n - 1)) == 0;
}

// C++
bool isPowerOfTwo(int32_t n) {
    return n > 0 && (n & (n - 1)) == 0;
}
// C++20 also provides std::has_single_bit(n) in <bit>

Count Set Bits (Brian Kernighan's Algorithm)

n & (n - 1) clears the lowest set bit. Repeat until n becomes 0, counting iterations. This runs in O(k) where k is the number of set bits, not the total bit width.

# Python
def count_set_bits(n: int) -> int:
    count = 0
    while n:
        n &= n - 1   # clear lowest set bit
        count += 1
    return count

# Python built-in: bin(n).count('1') or n.bit_count() (3.10+)

// Java
public int countSetBits(int n) {
    int count = 0;
    while (n != 0) {
        n &= n - 1;
        count++;
    }
    return count;
}
// Java built-in: Integer.bitCount(n) uses POPCNT intrinsic on modern JVMs

// C++
int countSetBits(int32_t n) {
    int count = 0;
    while (n) {
        n &= n - 1;
        count++;
    }
    return count;
}
// GCC/Clang built-in: __builtin_popcount(n) — compiles to a single POPCNT
// For 64-bit: __builtin_popcountll(n)
// C++20 standard: std::popcount(static_cast<uint32_t>(n))

Get / Set / Clear / Toggle the i-th Bit

# Python
def get_bit(n, i):    return (n >> i) & 1
def set_bit(n, i):    return n | (1 << i)
def clear_bit(n, i):  return n & ~(1 << i)
def toggle_bit(n, i): return n ^ (1 << i)

// Java
int getBit(int n, int i)    { return (n >> i) & 1; }
int setBit(int n, int i)    { return n | (1 << i); }
int clearBit(int n, int i)  { return n & ~(1 << i); }
int toggleBit(int n, int i) { return n ^ (1 << i); }

// C++  (use int32_t for explicit 32-bit width)
int32_t getBit(int32_t n, int i)    { return (n >> i) & 1; }
int32_t setBit(int32_t n, int i)    { return n | (1 << i); }
int32_t clearBit(int32_t n, int i)  { return n & ~(1 << i); }
int32_t toggleBit(int32_t n, int i) { return n ^ (1 << i); }

Isolate the Lowest Set Bit

n & (-n) returns a number with only the lowest set bit of n. This is the basis of Binary Indexed Trees (Fenwick Trees) and appears in many problems.

# Python
def lowest_set_bit(n: int) -> int:
    return n & (-n)
# 12 = 1100, -12 = ...0100 -> 1100 & 0100 = 0100 = 4

// Java
int lowestSetBit(int n) { return n & (-n); }
// Works identically because Java uses two's complement 32-bit ints

// C++
int32_t lowestSetBit(int32_t n) { return n & (-n); }
// GCC extension: __builtin_ctz(n) counts trailing zeros (same info)

3. XOR Patterns

XOR Properties & Classic Problems ▼

XOR has three properties that make it the star of bit manipulation interviews:

  • Self-inverse: a ^ a = 0
  • Identity: a ^ 0 = a
  • Commutative & Associative: order does not matter

Together these mean: XOR-ing a list of numbers cancels out every number that appears an even number of times, leaving only the odd-count numbers.

XOR Swap Step-by-Step: a=5, b=3
Initial State
a = 0101 = 5
b = 0011 = 3
Step 1: a ^= b
0101 ^ 0011 = 0110
a = 0110 = 6 (a XOR b)
b = 0011 = 3 (unchanged)
Step 2: b ^= a
0011 ^ 0110 = 0101
a = 0110 = 6 (unchanged)
b = 0101 = 5 (recovered a!)
Step 3: a ^= b
0110 ^ 0101 = 0011
a = 0011 = 3 (swapped!)
b = 0101 = 5 (swapped!)

Why it works: a stores a^b. When b ^= a, b gets (original b) ^ (a^b) = original a. When a ^= b (new b = original a), a gets (a^b) ^ a = original b.

LC #136: Single Number

Every element appears twice except one. XOR all elements; duplicates cancel, leaving the unique number.

# Python
def single_number(nums: list[int]) -> int:
    result = 0
    for n in nums:
        result ^= n
    return result
# O(n) time, O(1) space
# Pythonic one-liner: from functools import reduce; reduce(operator.xor, nums)

// Java
public int singleNumber(int[] nums) {
    int result = 0;
    for (int n : nums) result ^= n;
    return result;
}
// One-liner with streams: Arrays.stream(nums).reduce(0, (a, b) -> a ^ b)

// C++
int singleNumber(vector<int>& nums) {
    return accumulate(nums.begin(), nums.end(), 0, bit_xor<int>());
}
// Or simply: int r=0; for(int n:nums) r^=n; return r;

LC #268: Missing Number

Array of n numbers from 0..n with one missing. XOR all values with all indices 0..n; every number cancels except the missing one.

# Python
def missing_number(nums: list[int]) -> int:
    xor = len(nums)
    for i, num in enumerate(nums):
        xor ^= i ^ num
    return xor

// Java
public int missingNumber(int[] nums) {
    int xor = nums.length;
    for (int i = 0; i < nums.length; i++) {
        xor ^= i ^ nums[i];
    }
    return xor;
}

// C++
int missingNumber(vector<int>& nums) {
    int xorVal = nums.size();
    for (int i = 0; i < (int)nums.size(); i++)
        xorVal ^= i ^ nums[i];
    return xorVal;
}

LC #260: Single Number III (Two Unique Numbers)

Every element appears twice except two elements a and b. XOR all gives a ^ b. Since a != b, at least one bit differs. Use any differing bit to partition all numbers into two groups; XOR within each group recovers a and b separately.

# Python
def single_number_iii(nums: list[int]) -> list[int]:
    xor_all = 0
    for n in nums:
        xor_all ^= n

    # Isolate any bit where a and b differ
    diff_bit = xor_all & (-xor_all)  # lowest set bit

    a, b = 0, 0
    for n in nums:
        if n & diff_bit:
            a ^= n
        else:
            b ^= n
    return [a, b]

// Java
public int[] singleNumberIII(int[] nums) {
    int xorAll = 0;
    for (int n : nums) xorAll ^= n;

    // Lowest set bit of xorAll is a bit where the two unique nums differ
    int diffBit = xorAll & (-xorAll);

    int a = 0, b = 0;
    for (int n : nums) {
        if ((n & diffBit) != 0) a ^= n;
        else b ^= n;
    }
    return new int[]{a, b};
}

// C++
vector<int> singleNumberIII(vector<int>& nums) {
    int xorAll = 0;
    for (int n : nums) xorAll ^= n;

    int diffBit = xorAll & (-xorAll);

    int a = 0, b = 0;
    for (int n : nums) {
        if (n & diffBit) a ^= n;
        else b ^= n;
    }
    return {a, b};
}

Why the partition works: Every paired number has both copies in the same group (they share the same bit value at that position), so they cancel. The two unique numbers land in different groups because they differ at that bit.

Mask 0 (000) = empty set, mask 7 (111) = full set. Iterating mask from 0 to 2n-1 visits every subset exactly once.

# Python
def subsets(nums: list[int]) -> list[list[int]]:
    n = len(nums)
    result = []
    for mask in range(1 << n):  # 0 to 2^n - 1
        subset = [nums[i] for i in range(n) if mask & (1 << i)]
        result.append(subset)
    return result

// Java
public List<List<Integer>> subsets(int[] nums) {
    int n = nums.length;
    List<List<Integer>> result = new ArrayList<>();
    for (int mask = 0; mask < (1 << n); mask++) {
        List<Integer> subset = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            if ((mask & (1 << i)) != 0) subset.add(nums[i]);
        }
        result.add(subset);
    }
    return result;
}

// C++
vector<vector<int>> subsets(vector<int>& nums) {
    int n = nums.size();
    vector<vector<int>> result;
    for (int mask = 0; mask < (1 << n); mask++) {
        vector<int> subset;
        for (int i = 0; i < n; i++)
            if (mask & (1 << i)) subset.push_back(nums[i]);
        result.push_back(subset);
    }
    return result;
}

LC #461: Hamming Distance

The Hamming distance between two integers is the number of positions where their bits differ. XOR the two numbers (differing bits become 1), then count set bits.

# Python
def hamming_distance(x: int, y: int) -> int:
    xor = x ^ y
    count = 0
    while xor:
        xor &= xor - 1
        count += 1
    return count

// Java
public int hammingDistance(int x, int y) {
    return Integer.bitCount(x ^ y);
    // Integer.bitCount uses POPCNT hardware intrinsic on modern JVMs
}

// C++
int hammingDistance(int x, int y) {
    return __builtin_popcount(x ^ y);
}

LC #190: Reverse Bits

Reverse all 32 bits of a given unsigned integer. Process bit by bit from LSB to MSB.

# Python
def reverse_bits(n: int) -> int:
    result = 0
    for _ in range(32):
        result = (result << 1) | (n & 1)
        n >>= 1
    return result

// Java — note: parameter is int but treated as unsigned 32-bit
public int reverseBits(int n) {
    int result = 0;
    for (int i = 0; i < 32; i++) {
        result = (result << 1) | (n & 1);
        n >>>= 1;  // >>> is logical (unsigned) right shift — fills with 0
    }
    return result;
}
// Note: >>> matters here because n may be "negative" (MSB set).
// Using >> would sign-extend and produce wrong results.

// C++
uint32_t reverseBits(uint32_t n) {
    uint32_t result = 0;
    for (int i = 0; i < 32; i++) {
        result = (result << 1) | (n & 1);
        n >>= 1;  // safe: uint32_t, logical right shift
    }
    return result;
}
// C++20: std::byteswap handles byte-level, but bit reversal needs a loop or
// platform intrinsic (__builtin_bitreverse32 on some GCC versions)

def hamming_weight(n: int) -> int:

5. Practical Applications

Real-World Bit Manipulation ▼

Bloom Filters — Deep Dive

A bloom filter is a space-efficient probabilistic data structure that answers membership queries. It uses a bit array of m bits with k independent hash functions.

  • Insert: Hash the element k times, set each of the k bit positions to 1.
  • Query: Hash the element k times, check if all k positions are 1. If any is 0, definitely not present. If all are 1, probably present (may be a false positive).
  • False negatives: impossible. A set bit can never be unset.
  • False positives: possible. Multiple elements may set all bits at query positions.
The Math

After inserting n elements into a filter with m bits and k hash functions, the false positive rate is approximately:

FP rate ≈ (1 − e−kn/m)k

The optimal number of hash functions (minimizes FP rate for fixed m and n) is:

kopt = (m/n) × ln(2) ≈ 0.693 × (m/n)

Real-world numbers: Apache Cassandra uses bloom filters with ~10 bits per element and 10 hash functions, yielding roughly 1% false positive rate. LevelDB uses them to skip SST files that do not contain a queried key. Google Bigtable uses them to avoid unnecessary disk reads entirely for non-existent rows.

# Simple Bloom Filter in Python
import hashlib, math

class BloomFilter:
    def __init__(self, m: int, k: int):
        self.m = m          # bit array size
        self.k = k          # number of hash functions
        self.bits = 0       # use a single Python integer as bit array

    def _hash_positions(self, item: str):
        positions = set()
        for seed in range(self.k):
            digest = hashlib.md5(f"{seed}:{item}".encode()).hexdigest()
            positions.add(int(digest, 16) % self.m)
        return positions

    def add(self, item: str):
        for pos in self._hash_positions(item):
            self.bits |= (1 << pos)

    def __contains__(self, item: str) -> bool:
        return all((self.bits >> pos) & 1 for pos in self._hash_positions(item))

# Optimal parameters for 1% FP rate with 1000 elements:
n = 1000
fp_rate = 0.01
m = int(-n * math.log(fp_rate) / (math.log(2) ** 2))  # ~9585 bits
k = int(m / n * math.log(2))                           # ~7 functions
print(f"Optimal: m={m}, k={k}")

Feature Flags & Permissions

Unix file permissions use 3 bits per user class: rwx = read (4), write (2), execute (1). Checking permissions is a single AND: if (perms & WRITE_BIT). This pattern scales to feature flags in applications where each bit represents a feature toggle.

# Python — Permission flags
READ    = 0b100  # 4
WRITE   = 0b010  # 2
EXECUTE = 0b001  # 1

user_perms = READ | WRITE  # 0b110 = 6

can_read  = bool(user_perms & READ)     # True
can_exec  = bool(user_perms & EXECUTE)  # False

# Grant execute
user_perms |= EXECUTE   # 0b111 = 7
# Revoke write
user_perms &= ~WRITE    # 0b101 = 5

// Java — Permission flags (same pattern, different types)
public class Permissions {
    static final int READ    = 0b100;
    static final int WRITE   = 0b010;
    static final int EXECUTE = 0b001;

    int perms = READ | WRITE;  // 6

    boolean canRead()    { return (perms & READ) != 0; }
    boolean canWrite()   { return (perms & WRITE) != 0; }
    boolean canExecute() { return (perms & EXECUTE) != 0; }

    void grantExecute()  { perms |= EXECUTE; }
    void revokeWrite()   { perms &= ~WRITE; }

    // For 64 features: use long instead of int (64-bit flags)
    // For >64 features: use java.util.BitSet or EnumSet
}

7. Interview Follow-Up Questions

Questions Interviewers Ask After Your Initial Solution ▼

Once you solve a bit manipulation problem, a strong interviewer will probe your depth. Here are the most common follow-ups and strong answers.

How would you count set bits in O(1)?

Hint: lookup table or hardware instruction.

For small inputs (8-bit), precompute a lookup table of 256 entries (0–255) where each entry stores the popcount for that byte value. For a 32-bit integer, split into four bytes and sum: table[n & 0xFF] + table[(n>>8) & 0xFF] + .... This is O(1) time with O(256) = O(1) space after setup.

In practice, modern CPUs have a POPCNT hardware instruction. Java's Integer.bitCount() and C++'s __builtin_popcount() both compile to a single CPU instruction on x86-64 — true hardware O(1).

What is the difference between signed and unsigned right shift in Java? When does it matter?

>> (arithmetic): preserves the sign bit; shifting -8 right by 1 gives -4. Used for division by powers of 2 on signed integers.

>>> (logical/unsigned): fills with 0 regardless of sign. Shifting -8 (0xFFFFFFF8) right by 1 gives 0x7FFFFFFC = 2147483644.

When it matters: LC #190 (Reverse Bits) processes bits of the input integer as if they were unsigned. Using >> on a negative input would sign-extend and pollute the upper bits of the result. Always use >>> when treating Java ints as raw bit patterns. The same issue affects rolling hash problems where the window value may exceed Integer.MAX_VALUE.

How would you implement addition without the + operator using bit manipulation?

Use the ripple-carry adder model: sum = a ^ b gives bits that are different (no carry), and carry = (a & b) << 1 gives bits that need to be carried. Repeat with a = sum, b = carry until carry is 0.

def add_no_plus(a: int, b: int) -> int:
    mask = 0xFFFFFFFF  # simulate 32-bit
    while b & mask:
        carry = (a & b) << 1
        a = a ^ b
        b = carry
    # Handle Python's arbitrary precision for negative results
    return (a & mask) if (a & 0x80000000) else a

Can you use bit manipulation to solve the Power Set problem? How does it compare to backtracking?

Bitmask approach: Iterate mask from 0 to 2n−1. For each mask, the bits indicate which elements are included. O(n·2n) time, same as backtracking.

Trade-offs vs backtracking:

  • Bitmask is iterative (no recursion overhead, no stack depth concerns), easier to parallelize.
  • Backtracking is more flexible for pruning (e.g., constraint satisfaction) and handles n > 64 without needing BigInteger.
  • Bitmask becomes impractical at n > ~30 due to memory; backtracking can generate subsets lazily via a generator.

Interviewers want you to articulate the trade-offs, not just say "both are O(2n)".

Why are Bloom filters used in databases like Cassandra and LevelDB?

These databases use LSM (Log-Structured Merge) trees or SSTables where data is spread across multiple disk files. A point lookup for a key might require reading many files to determine the key does not exist — a very expensive I/O operation.

Bloom filters act as a fast "definitely not here" gate before any disk I/O. Each SST file has its own filter. On a read: check the in-memory bloom filter first. If the filter says "no", skip the file entirely. If it says "maybe", do the disk read. With a 1% FP rate and 10 bits per element, you eliminate >99% of unnecessary disk reads with negligible memory overhead (1.25 bytes per element for 10 bits).

Q1
What does n & (n-1) do?

A1
Clears the lowest set bit. Used in Brian Kernighan's algorithm (count set bits in O(k) iterations) and power-of-2 check (n > 0 && (n & (n-1)) == 0).
Q2
What does n & (-n) do?
Click to reveal answer
A2
Isolates the lowest set bit. Used in Fenwick Trees (Binary Indexed Trees) and Single Number III to split groups by any differing bit.
Q3
Why does XOR-ing all elements find the single unique number?
Click to reveal answer
A3
XOR is self-inverse (a^a=0) and associative. All paired elements cancel out (a^a=0), and XOR with 0 is identity (a^0=a), leaving only the unique element.
Q4
How does Single Number III separate two unique numbers?
Click to reveal answer
A4
XOR all gives a^b. Isolate any differing bit (use (a^b) & (-(a^b))). Partition all numbers by that bit — pairs stay together (both copies in same group), so a and b land in different groups. XOR each group to recover them.
Q5
Why must you mask to 32 bits in Python for bit manipulation problems?
Click to reveal answer
A5
Python has arbitrary-precision integers, so ~5 = -6 with infinite leading 1s — not 32-bit two's complement. Mask with 0xFFFFFFFF to simulate 32-bit behavior. Also convert back to signed: if result > 0x7FFFFFFF: result -= 0x100000000.
Q6
What is the false positive rate formula for a Bloom filter?
Click to reveal answer
A6
Approximately (1 − e−kn/m)k where k = hash functions, n = elements inserted, m = bit array size. Optimal k = (m/n)·ln(2) ≈ 0.693·(m/n). For 1% FP rate: ~10 bits/element, ~7 hash functions.
