1. Trie Implementation

Core Trie — Insert, Search, StartsWith, Delete ▼

A trie (prefix tree) stores strings character-by-character. Each edge represents a character, and each node may mark the end of a word. Tries give O(L) lookup where L is the word length, independent of how many words are stored — unlike hash tables which degrade under collisions.

Why tries matter in interviews: They are the canonical solution for prefix-based queries (autocomplete, spell check, IP routing). Google's search suggestion box is conceptually a trie with ranking.

Full Implementation (Python)

class TrieNode:
    __slots__ = ('children', 'is_end')
    def __init__(self):
        self.children = {}   # char -> TrieNode
        self.is_end = False

class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word: str) -> None:
        node = self.root
        for ch in word:
            if ch not in node.children:
                node.children[ch] = TrieNode()
            node = node.children[ch]
        node.is_end = True

    def search(self, word: str) -> bool:
        node = self._find(word)
        return node is not None and node.is_end

    def startsWith(self, prefix: str) -> bool:
        return self._find(prefix) is not None

    def _find(self, prefix: str):
        node = self.root
        for ch in prefix:
            if ch not in node.children:
                return None
            node = node.children[ch]
        return node

    def delete(self, word: str) -> bool:
        """Returns True if word was deleted. Uses post-order cleanup."""
        def _delete(node, word, depth):
            if depth == len(word):
                if not node.is_end:
                    return False
                node.is_end = False
                return len(node.children) == 0  # can prune?
            ch = word[depth]
            if ch not in node.children:
                return False
            should_prune = _delete(node.children[ch], word, depth + 1)
            if should_prune:
                del node.children[ch]
                return not node.is_end and len(node.children) == 0
            return False
        _delete(self.root, word, 0)
        return True

Full Implementation (Java)

import java.util.HashMap;
import java.util.Map;

class TrieNode {
    Map<Character, TrieNode> children = new HashMap<>();
    boolean isEnd = false;
}

class Trie {
    private final TrieNode root = new TrieNode();

    public void insert(String word) {
        TrieNode node = root;
        for (char ch : word.toCharArray()) {
            node.children.putIfAbsent(ch, new TrieNode());
            node = node.children.get(ch);
        }
        node.isEnd = true;
    }

    public boolean search(String word) {
        TrieNode node = find(word);
        return node != null && node.isEnd;
    }

    public boolean startsWith(String prefix) {
        return find(prefix) != null;
    }

    private TrieNode find(String prefix) {
        TrieNode node = root;
        for (char ch : prefix.toCharArray()) {
            if (!node.children.containsKey(ch)) return null;
            node = node.children.get(ch);
        }
        return node;
    }

    public boolean delete(String word) {
        return deleteHelper(root, word, 0);
    }

    // Returns true if the current node can be pruned
    private boolean deleteHelper(TrieNode node, String word, int depth) {
        if (depth == word.length()) {
            if (!node.isEnd) return false;
            node.isEnd = false;
            return node.children.isEmpty();
        }
        char ch = word.charAt(depth);
        TrieNode child = node.children.get(ch);
        if (child == null) return false;
        boolean shouldPrune = deleteHelper(child, word, depth + 1);
        if (shouldPrune) {
            node.children.remove(ch);
            return !node.isEnd && node.children.isEmpty();
        }
        return false;
    }
}

2. Classic Trie Problems

LeetCode #211 — Design Add and Search Words (Wildcard) ▼

Problem: Design a data structure that supports addWord(word) and search(word) where search can contain . as a wildcard matching any single character.

Key insight: Standard trie insert; for search, when you hit a ., branch into all children recursively.

Python

class WordDictionary:
    def __init__(self):
        self.root = TrieNode()

    def addWord(self, word: str) -> None:
        node = self.root
        for ch in word:
            if ch not in node.children:
                node.children[ch] = TrieNode()
            node = node.children[ch]
        node.is_end = True

    def search(self, word: str) -> bool:
        def dfs(node, i):
            if i == len(word):
                return node.is_end
            if word[i] == '.':
                return any(dfs(child, i + 1)
                           for child in node.children.values())
            if word[i] not in node.children:
                return False
            return dfs(node.children[word[i]], i + 1)
        return dfs(self.root, 0)

Java

class WordDictionary {
    private final TrieNode root = new TrieNode();

    public void addWord(String word) {
        TrieNode node = root;
        for (char ch : word.toCharArray()) {
            node.children.putIfAbsent(ch, new TrieNode());
            node = node.children.get(ch);
        }
        node.isEnd = true;
    }

    public boolean search(String word) {
        return dfs(root, word, 0);
    }

    private boolean dfs(TrieNode node, String word, int i) {
        if (i == word.length()) return node.isEnd;
        char ch = word.charAt(i);
        if (ch == '.') {
            for (TrieNode child : node.children.values()) {
                if (dfs(child, word, i + 1)) return true;
            }
            return false;
        }
        TrieNode child = node.children.get(ch);
        return child != null && dfs(child, word, i + 1);
    }
}

Time: O(L) for addWord. O(26^L) worst case for search with all dots, but in practice much faster due to pruning.

LeetCode #212 — Word Search II (Trie + Backtracking) ▼

Problem: Given an m×n board of characters and a list of words, find all words that can be formed by sequentially adjacent cells (no cell reused per word).

Why trie: A naive approach searches for each word independently (O(words × m×n × 4^L)). Building a trie of all target words lets you search for all words simultaneously in a single board traversal.

Python

def findWords(board, words):
    root = TrieNode()
    for w in words:                # build trie of target words
        node = root
        for ch in w:
            if ch not in node.children:
                node.children[ch] = TrieNode()
            node = node.children[ch]
        node.word = w              # store full word at terminal

    result = []
    rows, cols = len(board), len(board[0])

    def dfs(r, c, node):
        ch = board[r][c]
        if ch not in node.children:
            return
        child = node.children[ch]
        if hasattr(child, 'word') and child.word:
            result.append(child.word)
            child.word = None      # avoid duplicates

        board[r][c] = '#'          # mark visited
        for dr, dc in ((0,1),(0,-1),(1,0),(-1,0)):
            nr, nc = r + dr, c + dc
            if 0 <= nr < rows and 0 <= nc < cols and board[nr][nc] != '#':
                dfs(nr, nc, child)
        board[r][c] = ch           # restore

        if not child.children:     # prune empty branches
            del node.children[ch]

    for r in range(rows):
        for c in range(cols):
            dfs(r, c, root)
    return result

Java

import java.util.*;

class Solution {
    private static class WNode {
        Map<Character, WNode> children = new HashMap<>();
        String word = null;
    }

    public List<String> findWords(char[][] board, String[] words) {
        WNode root = new WNode();
        for (String w : words) {
            WNode node = root;
            for (char ch : w.toCharArray()) {
                node.children.putIfAbsent(ch, new WNode());
                node = node.children.get(ch);
            }
            node.word = w;
        }

        List<String> result = new ArrayList<>();
        int rows = board.length, cols = board[0].length;

        for (int r = 0; r < rows; r++)
            for (int c = 0; c < cols; c++)
                dfs(board, r, c, root, result);

        return result;
    }

    private void dfs(char[][] board, int r, int c, WNode node, List<String> result) {
        if (r < 0 || r >= board.length || c < 0 || c >= board[0].length) return;
        char ch = board[r][c];
        if (ch == '#' || !node.children.containsKey(ch)) return;

        WNode child = node.children.get(ch);
        if (child.word != null) {
            result.add(child.word);
            child.word = null;  // deduplicate
        }

        board[r][c] = '#';
        int[][] dirs = {{0,1},{0,-1},{1,0},{-1,0}};
        for (int[] d : dirs)
            dfs(board, r + d[0], c + d[1], child, result);
        board[r][c] = ch;

        if (child.children.isEmpty())  // prune dead branch
            node.children.remove(ch);
    }
}

Optimization: The del node.children[ch] / node.children.remove(ch) prune step is critical. Without it, you repeatedly explore dead branches. This brings the solution from TLE to accepted.

LeetCode #1268 — Search Suggestions System (Autocomplete) ▼

Problem: Given an array of products and a search word, after each character typed return the top 3 lexicographically smallest matches.

Approach: Sort products, build a trie, store sorted words at each node (or collect via DFS). Alternatively, use binary search on the sorted list for each prefix — simpler and often preferred in interviews.

Python

def suggestedProducts(products, searchWord):
    products.sort()
    result, prefix = [], ""
    for ch in searchWord:
        prefix += ch
        # Binary search for leftmost match
        import bisect
        i = bisect.bisect_left(products, prefix)
        suggestions = []
        for j in range(i, min(i + 3, len(products))):
            if products[j].startswith(prefix):
                suggestions.append(products[j])
        result.append(suggestions)
    return result

Java

import java.util.*;

class Solution {
    public List<List<String>> suggestedProducts(String[] products, String searchWord) {
        Arrays.sort(products);
        List<List<String>> result = new ArrayList<>();
        String prefix = "";

        for (char ch : searchWord.toCharArray()) {
            prefix += ch;
            // Binary search: find leftmost candidate
            int lo = 0, hi = products.length;
            while (lo < hi) {
                int mid = (lo + hi) / 2;
                if (products[mid].compareTo(prefix) < 0) lo = mid + 1;
                else hi = mid;
            }
            List<String> suggestions = new ArrayList<>();
            for (int j = lo; j < Math.min(lo + 3, products.length); j++) {
                if (products[j].startsWith(prefix)) suggestions.add(products[j]);
            }
            result.add(suggestions);
        }
        return result;
    }
}

Interview tip: Mention both approaches. The trie approach is O(total chars) to build but O(1) per prefix lookup. The binary search approach is O(n log n) sort + O(L log n) per query. For a one-shot query, binary search wins; for a persistent autocomplete service, the trie wins.

3. Segment Tree

Build, Query, Update for Range Sum ▼

When to use: You need both range queries (sum/min/max over [l, r]) and point or range updates. A prefix sum handles range queries in O(1) but updates cost O(n). A segment tree gives O(log n) for both.

Real-world usage: Database engines use segment-tree-like structures for range index scans. Competitive programming staple for problems involving mutable ranges.

graph TD N1["[0,3] sum=10"] --> N2["[0,1] sum=3"] N1 --> N3["[2,3] sum=7"] N2 --> N4["[0] val=1"] N2 --> N5["[1] val=2"] N3 --> N6["[2] val=3"] N3 --> N7["[3] val=4"]

Segment tree for array [1, 2, 3, 4]. Each node stores the sum of its range.

Compact Array-Based Implementation (Python)

class SegmentTree:
    """Range sum queries + point updates in O(log n)."""
    def __init__(self, nums):
        self.n = len(nums)
        self.tree = [0] * (2 * self.n)
        # Build: fill leaves, then internal nodes
        for i in range(self.n):
            self.tree[self.n + i] = nums[i]
        for i in range(self.n - 1, 0, -1):
            self.tree[i] = self.tree[2*i] + self.tree[2*i+1]

    def update(self, i, val):
        """Set nums[i] = val."""
        i += self.n
        self.tree[i] = val
        while i > 1:
            i //= 2
            self.tree[i] = self.tree[2*i] + self.tree[2*i+1]

    def query(self, l, r):
        """Return sum of nums[l..r] inclusive."""
        res = 0
        l += self.n
        r += self.n + 1
        while l < r:
            if l & 1:
                res += self.tree[l]
                l += 1
            if r & 1:
                r -= 1
                res += self.tree[r]
            l //= 2
            r //= 2
        return res

Compact Array-Based Implementation (Java)

class SegmentTree {
    private final int n;
    private final int[] tree;

    public SegmentTree(int[] nums) {
        n = nums.length;
        tree = new int[2 * n];
        // Fill leaves
        for (int i = 0; i < n; i++) tree[n + i] = nums[i];
        // Build internal nodes bottom-up
        for (int i = n - 1; i > 0; i--) tree[i] = tree[2*i] + tree[2*i+1];
    }

    /** Set nums[i] = val. O(log n). */
    public void update(int i, int val) {
        i += n;
        tree[i] = val;
        while (i > 1) {
            i /= 2;
            tree[i] = tree[2*i] + tree[2*i+1];
        }
    }

    /** Return sum of nums[l..r] inclusive. O(log n). */
    public int query(int l, int r) {
        int res = 0;
        l += n;
        r += n + 1;
        while (l < r) {
            if ((l & 1) == 1) res += tree[l++];
            if ((r & 1) == 1) res += tree[--r];
            l /= 2;
            r /= 2;
        }
        return res;
    }
}

Complexity: Build O(n), query O(log n), update O(log n). Space O(2n) = O(n).

Why this implementation? The iterative bottom-up approach (often called "Codeforces-style") avoids recursion overhead and is half the code of the recursive version. Node i's children are 2i and 2i+1. Leaves are at indices [n, 2n).

4. Fenwick Tree (Binary Indexed Tree)

Point Update + Prefix Query ▼

A Fenwick tree supports prefix sum queries and point updates both in O(log n), using only a flat array of size n+1. It is simpler and has lower constant factors than a segment tree, but less general (no lazy propagation, harder to adapt to min/max).

Implementation (Python)

class FenwickTree:
    """1-indexed Binary Indexed Tree for prefix sums."""
    def __init__(self, n):
        self.n = n
        self.tree = [0] * (n + 1)

    def update(self, i, delta):
        """Add delta to index i (1-indexed)."""
        while i <= self.n:
            self.tree[i] += delta
            i += i & (-i)    # add lowest set bit

    def query(self, i):
        """Return prefix sum [1..i]."""
        s = 0
        while i > 0:
            s += self.tree[i]
            i -= i & (-i)    # remove lowest set bit
        return s

    def range_query(self, l, r):
        """Return sum [l..r] (1-indexed)."""
        return self.query(r) - self.query(l - 1)

Implementation (Java)

class FenwickTree {
    private final int n;
    private final int[] tree;

    public FenwickTree(int n) {
        this.n = n;
        this.tree = new int[n + 1];
    }

    /** Add delta to position i (1-indexed). O(log n). */
    public void update(int i, int delta) {
        for (; i <= n; i += i & (-i))
            tree[i] += delta;
    }

    /** Prefix sum [1..i] (1-indexed). O(log n). */
    public int query(int i) {
        int s = 0;
        for (; i > 0; i -= i & (-i))
            s += tree[i];
        return s;
    }

    /** Range sum [l..r] (1-indexed). O(log n). */
    public int rangeQuery(int l, int r) {
        return query(r) - query(l - 1);
    }
}

Range Update + Point Query with Two Fenwick Trees ▼

A standard Fenwick tree does point update + range query. But sometimes you need the opposite: add delta to all elements in [l, r] (range update) and then read the value at a single index (point query). This is the "difference array" trick applied to a BIT.

The Idea: Difference Array BIT

Define a difference array D where D[i] = A[i] - A[i-1]. Then A[i] = prefix_sum(D, i). A range update A[l..r] += delta becomes two point updates on D:

  • D[l] += delta — starts the addition at index l
  • D[r+1] -= delta — cancels it after index r

Point query A[i] becomes a prefix sum on D up to i.

When Range Update + Point Query > Point Update + Range Query

Scenario Better Choice
Apply promotions to all items in a price range, then query individual pricesRange Update + Point Query
Count elements in a value range after point insertionsPoint Update + Range Query
Accumulate votes in a score range, then read final score per userRange Update + Point Query
Sliding window frequency countsPoint Update + Range Query

Python: Range Update + Point Query

class FenwickRangeUpdate:
    """1-indexed BIT supporting range [l,r] += delta and point query."""
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 2)   # extra slot for r+1

    def _add(self, i, delta):
        while i <= self.n:
            self.bit[i] += delta
            i += i & (-i)

    def _prefix(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & (-i)
        return s

    def range_update(self, l, r, delta):
        """Add delta to all A[l..r]."""
        self._add(l, delta)
        self._add(r + 1, -delta)

    def point_query(self, i):
        """Return A[i] after all updates."""
        return self._prefix(i)


# Example usage
bit = FenwickRangeUpdate(10)
bit.range_update(2, 5, 3)   # A[2..5] += 3
bit.range_update(4, 8, 1)   # A[4..8] += 1
print(bit.point_query(4))   # 4 (3 + 1)
print(bit.point_query(6))   # 1

Java: Range Update + Point Query

class FenwickRangeUpdate {
    private final int n;
    private final long[] bit;

    public FenwickRangeUpdate(int n) {
        this.n = n;
        this.bit = new long[n + 2];
    }

    private void add(int i, long delta) {
        for (; i <= n; i += i & (-i))
            bit[i] += delta;
    }

    private long prefix(int i) {
        long s = 0;
        for (; i > 0; i -= i & (-i))
            s += bit[i];
        return s;
    }

    /** Add delta to all positions in [l, r] (1-indexed). O(log n). */
    public void rangeUpdate(int l, int r, long delta) {
        add(l, delta);
        add(r + 1, -delta);
    }

    /** Return the value at position i after all updates. O(log n). */
    public long pointQuery(int i) {
        return prefix(i);
    }

    // --- If you also need range sum queries after range updates ---
    // Use the two-BIT technique: maintain bit1 and bit2 such that
    // prefix_sum(A, i) = bit1.prefix(i) * i - bit2.prefix(i)
}

Two-BIT technique for range update + range query: If you need BOTH range updates AND range sum queries simultaneously, maintain two BITs. The identity is: sum(A[1..i]) = prefix(B1, i) * i - prefix(B2, i) where B1 and B2 are auxiliary BITs updated according to a mathematical derivation. This is an advanced technique rarely needed in interviews but good to know exists.

5. Advanced Data Structures Overview

Skip Lists, Bloom Filters, Count-Min Sketch ▼

Skip List

A randomized structure layering sorted linked lists with express lanes. Expected O(log n) search/insert/delete. Used by Redis for sorted sets — simpler than balanced BSTs, supports range scans, and amenable to lock-free concurrency.

Bloom Filter

A space-efficient probabilistic set: no false negatives, possible false positives. Uses k hash functions mapping to a bit array of size m. False positive rate ~(1 - e^(-kn/m))^k.

Uses: Chrome safe browsing, Cassandra (skip disk reads for missing keys), Medium (avoid re-recommending articles).

Count-Min Sketch

A probabilistic frequency table using d hash functions × w counters. Query returns minimum across d positions (overcounts possible, undercounts not). Used for network anomaly detection and trending topic identification.

Skip ListExact ordered setNoneO(n) expected

6. Real-World Applications at Scale

How Tries and Advanced DS Power Production Systems ▼

Lucene / Elasticsearch — FST (Finite State Transducer)

Apache Lucene, the engine beneath Elasticsearch, stores its inverted index terms in a Finite State Transducer — a compressed trie variant that maps terms to file offsets with dramatically less memory than a naive trie. Key properties:

  • Shared prefixes and shared suffixes are deduplicated, unlike a standard trie that only shares prefixes.
  • An FST over 1 million terms can fit in a few MB vs hundreds of MB for a hash map.
  • Prefix queries (autocomplete), range queries ("all terms starting with 'ab'...'az'"), and fuzzy search with edit distance all operate efficiently on the FST.
  • At Elasticsearch scale (100 billion documents, petabytes of data), the FST lives in OS page cache and is traversed on every search.

Interview relevance: When asked "how would you design an autocomplete for a search engine," mentioning FSTs as a production-grade compressed trie signals depth beyond textbook knowledge.

Redis Sorted Sets — Skip Lists

Redis implements its ZSET (sorted set) using a skip list + hash map combo:

  • The skip list provides O(log n) rank queries and range scans by score.
  • The hash map provides O(1) score lookups by member name.
  • Memory overhead: ~64 bytes per element (4 forward pointers on average at level 1/4 promotion probability).
  • Common production usage: leaderboards, rate limiting with sliding windows, geospatial indexing (via GEOADD which encodes lat/lng as a sorted score).

Redis chose skip lists over balanced BSTs because they are simpler to implement correctly in a single-threaded async event loop, and range operations translate naturally to forward pointer traversal.

T9 Predictive Text — Digit-Path Trie

T9 (Text on 9 keys) maps digit sequences to words. The phone keypad assigns 3-4 letters per digit (2=abc, 3=def, …). A production T9 implementation:

  • Builds a trie over a 60,000-word dictionary.
  • Augments each node with the digit sequence that reaches it.
  • Query for digit sequence "4663" returns all words with path d-o-m/n/e/f — "good", "gone", "home", etc.
  • Modern implementations add frequency weights so the most commonly typed word appears first, a good interview follow-up: "how would you rank suggestions?"

IP Routing Tables — Patricia Tries (Radix Trees)

Every internet router performs a longest prefix match on the destination IP address to find the next hop. With millions of route prefixes, performance is critical:

  • A standard binary trie over 32-bit IPv4 addresses has depth 32, each level a 0/1 branch.
  • A Patricia trie (radix tree) collapses single-child chains into single edges labeled with the skipped bits, reducing depth to O(number of distinct prefixes) instead of 32.
  • Linux kernel's fib_trie uses a Level-Compressed Trie (LC-Trie) that achieves ~4 memory accesses per lookup in practice.
  • Hardware routers use TCAM (Ternary Content Addressable Memory) for sub-nanosecond lookup, but software fallback always uses a radix tree.

Connection to interviews: "Design a URL router" or "implement wildcard route matching" — both are radix tree problems at their core.

8. Interview Follow-Up Questions

Click "Show Guidance" on each to reveal a sample answer direction.

  • How would you implement autocomplete with ranking (not just lexicographic order)?
    Show Guidance ↓
    Store a frequency/score at each end-of-word node. During prefix traversal, collect all terminal nodes reachable from the prefix node and return the top-k by score. For production systems, store the top-k pre-computed at every internal node (updated incrementally on each query). This trades memory (O(n * k) extra) for O(L + k) query time. Alternatively, use a min-heap of size k during DFS to avoid materializing all candidates.
  • What's the space complexity of a trie vs a hash set for storing N words of average length L?
    Show Guidance ↓
    A trie uses O(N × L) nodes in the worst case (no shared prefixes), but O(total unique characters) in the best case when all words share a long common prefix. Each node is ~56 bytes in Python (dict overhead). A hash set uses O(N × L) bytes for the string storage plus O(N) for the set entries. In practice, tries use more memory than hash sets when words have short or no shared prefixes, but win on prefix query operations. For competitive programming, array[26] trie nodes are 208 bytes each — allocating 100k nodes = ~20MB, usually within limits.
  • How would you handle deletion in a segment tree with lazy propagation?
    Show Guidance ↓
    In a lazy segment tree, each node carries a "pending" tag representing deferred updates to its subtree. On deletion (range update to subtract), you apply the lazy tag to the node's aggregate value and push it down to children before recursing. The push-down step is: child.lazy += parent.lazy; child.value += child.lazy * child.range_size; parent.lazy = 0. Point deletions without lazy are O(log n). The key invariant is that lazy tags accumulate and are only resolved (pushed down) when you need to access a node's children.
  • Can you use a Fenwick tree for range minimum queries? Why or why not?
    Show Guidance ↓
    Not natively, and this is a key limitation. Fenwick trees work by decomposing prefix sums using the lowest-set-bit trick, which relies on the additive inverse (subtraction). Minimum has no inverse: min(l, r) cannot be computed from prefix_min(r) - prefix_min(l-1) because minimum is not invertible. You can build a Fenwick tree for prefix minimums (minimum of A[1..i]), but this only supports point updates in one direction (decreasing) and the range query is limited to [1..i]. For arbitrary range min queries with updates, a Segment tree is the correct structure.
  • How does a radix tree (Patricia trie) improve on a standard trie?
    Show Guidance ↓
    A standard trie has a node for every character, creating long chains of single-child nodes for words with unique suffixes. A Patricia trie (Practical Algorithm to Retrieve Information Coded in Alphanumeric, or more commonly just "radix tree") collapses every chain of single-child nodes into a single edge labeled with the entire substring. This reduces: (1) node count from O(total characters) to O(number of keys); (2) tree height from O(max key length) to O(number of keys); (3) memory significantly for sparse key sets. The tradeoff is that edge labels can be variable-length strings, complicating implementation. Patricia tries are used in Linux kernel routing tables, Go's standard library HTTP router, and the Rust regex engine.

When you only need prefix sums + point updates. Fenwick is simpler (~15 lines), has lower constant factors, and uses less memory (n+1 vs 2n–4n).
