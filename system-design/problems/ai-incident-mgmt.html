Design: AI-Powered Incident Management System

Examples: PagerDuty Copilot, ServiceNow AIOps, Datadog Watchdog, Custom PRX Agent Systems

Difficulty: Hard (Staff-Level) | Time: 45-60 minutes

1. Requirements Clarification

Functional Requirements ▼
  • Alert ingestion: Receive alerts from PagerDuty, Datadog, Grafana, CloudWatch (multi-source, normalized)
  • Automated triage: Classify severity, deduplicate correlated alerts, route to correct pipeline
  • AI-powered diagnosis: Agent investigates using logs (Splunk/ELK), metrics (Prometheus/Grafana), traces (Jaeger), and CMDB
  • Remediation execution: Suggest or auto-execute fixes (restart, scale, rollback) with approval workflow
  • Post-incident summarization: Generate timeline, root cause analysis, and action items automatically
  • Multi-agent orchestration: Triage, diagnostic, remediation, and summary agents with shared state
  • Human-in-the-loop: Approval gates for high-risk actions, escalation for low-confidence diagnoses
  • Runbook integration: RAG over runbook library for automated playbook execution
Non-Functional Requirements ▼
  • Latency: Initial triage < 30s, full diagnosis < 5 min, remediation < 10 min
  • Availability: 99.99% — must be more reliable than systems it monitors
  • Safety: No automated action without approval for P1/P2 incidents. Zero tolerance for making incidents worse.
  • Auditability: Immutable log of every agent decision and action (SOX/SOC2 compliant)
  • Cost: Optimized LLM usage — small model for triage, large model for complex diagnosis
  • Scalability: Handle 10K alerts/day with burst capacity for cascading failures

Key Design Decisions

  • Shared state (Redis): All agents read/write a shared context keyed by incident_id. Enables parallel investigation and prevents duplicate work.
  • Model routing: Triage uses GPT-4o-mini (fast, cheap). Diagnosis uses GPT-4o (accurate). Summary can use either based on incident complexity.
  • Parallel execution: Log and metric agents run in parallel (5s SLO). Use asyncio.wait with timeout; proceed with partial results if one source times out.
  • Conflict resolution: If log agent says "deployment regression" but metric agent says "traffic spike," the diagnostic agent weighs evidence quality and may request additional data.

5. Deep Dive: Safety & Governance

Safety Architecture ▼

Safety Principles

  • Least privilege: Each agent gets scoped credentials. Triage = read-only. Remediation = write to specific services only, time-limited.
  • Circuit breakers: If remediation agent causes 3 failures in 30 min, disable auto-remediation globally. Require human override to re-enable.
  • Immutable audit trail: Hash-chained log of every agent decision, tool call, LLM prompt/response, and approval. SOX/SOC2 compliant.
  • Deterministic fallback: When LLM is unavailable, fall back to rule-based pattern matching for known incident types. Escalate unknown types to human.

7. Failure Modes & Mitigations

What Can Go Wrong ▼
Failure Mitigation
LLM provider outage Multi-provider routing (OpenAI → Anthropic → on-prem fallback). Rule-based triage as last resort.
Wrong diagnosis → wrong fix Confidence thresholds, staged rollout (canary catches bad fixes), auto-rollback on metric degradation.
Remediation makes things worse Canary stage (5%) catches this. Auto-rollback. Circuit breaker disables that remediation type.
Circular alerts (agent action triggers new alert) Dedup window: suppress alerts for same service within 10 min of agent action. Max actions/incident.
Agent platform itself is down Separate infrastructure (different cluster/region). No shared dependencies. Graceful degradation to manual workflow. Self-monitoring by humans.
Alert storm (cascading failure, 1000x normal volume) Kafka backpressure, aggressive dedup, rate-limit LLM calls, batch similar alerts into single investigation.

8. Interview Tips

How to Ace This Question ▼

Do

  • Start with requirements and constraints, not the AI part
  • Lead with safety: "Before I discuss agent capabilities, let me address how we prevent the agent from making incidents worse"
  • Discuss how to make the system more reliable than what it monitors (separate infra, no shared deps)
  • Show cost awareness: model routing, semantic caching, classical ML pre-filtering
  • Mention graceful degradation: system should still work as a dashboard without AI

Don't

  • Jump straight to "we'll use GPT-4 to fix production" without safety discussion
  • Design the system assuming the LLM is always correct
  • Ignore the "agent platform availability" problem
  • Forget audit trails and compliance (especially for financial firms)
  • Over-automate: not every incident should be auto-remediated

Key Talking Points for Staff Level

  • Classical ML + GenAI unification: "Anomaly detection models feed alerts into the agent pipeline. The ML model detects, the agent reasons."
  • Progressive trust model: "Start read-only (Phase 1: diagnosis assistance). Then suggest actions (Phase 2). Then auto-execute low-risk (Phase 3). Full automation is Phase 4, only after months of data."
  • Measurable outcomes: "Success metric is MTTR reduction, not AI accuracy. If MTTR drops from 45 min to 12 min with 80% diagnosis accuracy, that's a win."
