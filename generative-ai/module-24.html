1. Time-Series Forecasting

Why Forecasting Matters for Operations ▼

Use Cases

  • Capacity planning: "Will we need more pods next Tuesday at 2pm?" (forecast request volume)
  • Cost forecasting: "At current growth, what's our cloud bill in 3 months?"
  • Proactive alerting: "Latency will breach SLO in 2 hours at current trend" (predict before it breaks)
  • Traffic shaping: "Scale up at 7am because we predict a 3x traffic spike"
ARIMA / SARIMA ▼

Intuition

ARIMA = AutoRegressive Integrated Moving Average. It models a time series as a combination of:

  • AR (AutoRegressive): Current value depends on past values. "Tomorrow's traffic looks like today's traffic."
  • I (Integrated): Differencing to make non-stationary data stationary. "Remove the trend first."
  • MA (Moving Average): Current value depends on past forecast errors. "Correct for recent prediction mistakes."

Parameters: ARIMA(p, d, q) where p=AR order, d=differencing order, q=MA order. SARIMA adds seasonal components: SARIMA(p,d,q)(P,D,Q,s) where s=seasonal period.

"""ARIMA/SARIMA for request volume forecasting."""
import pandas as pd
import numpy as np
from statsmodels.tsa.statespace.sarimax import SARIMAX
from statsmodels.tsa.stattools import adfuller
import warnings
warnings.filterwarnings('ignore')


def check_stationarity(series: pd.Series) -> dict:
    """Augmented Dickey-Fuller test for stationarity."""
    result = adfuller(series.dropna())
    return {
        "adf_statistic": result[0],
        "p_value": result[1],
        "is_stationary": result[1] < 0.05,
        "suggestion": "No differencing needed" if result[1] < 0.05
                      else "Apply differencing (d=1)"
    }


def fit_sarima(data: pd.Series, forecast_hours: int = 24) -> dict:
    """Fit SARIMA model to hourly metrics data and forecast."""
    # Auto-determine differencing
    d = 0 if check_stationarity(data)["is_stationary"] else 1

    # Fit SARIMA with hourly seasonality (s=24)
    model = SARIMAX(
        data,
        order=(2, d, 1),           # (p, d, q) - AR(2), MA(1)
        seasonal_order=(1, 1, 1, 24),  # Daily seasonality
        enforce_stationarity=False,
        enforce_invertibility=False,
    )
    results = model.fit(disp=False)

    # Forecast
    forecast = results.get_forecast(steps=forecast_hours)
    mean = forecast.predicted_mean
    ci = forecast.conf_int(alpha=0.05)

    return {
        "forecast": mean.values.tolist(),
        "lower_bound": ci.iloc[:, 0].values.tolist(),
        "upper_bound": ci.iloc[:, 1].values.tolist(),
        "aic": results.aic,
        "forecast_hours": forecast_hours,
    }

Prophet (Meta) ▼

Why Prophet

Prophet decomposes time series into trend + seasonality + holidays. Much simpler to use than ARIMA, handles missing data, and is great for business metrics with known seasonal patterns.

"""Prophet for capacity planning forecasting."""
from prophet import Prophet
import pandas as pd


def forecast_with_prophet(data: pd.DataFrame, periods: int = 168,
                           freq: str = "h") -> dict:
    """
    Forecast using Prophet. Data must have 'ds' (datetime) and 'y' (value) columns.

    Args:
        data: DataFrame with 'ds' and 'y' columns
        periods: Number of periods to forecast (168 = 1 week hourly)
        freq: Frequency ('h' for hourly, 'D' for daily)
    """
    model = Prophet(
        yearly_seasonality=True,
        weekly_seasonality=True,
        daily_seasonality=True,
        changepoint_prior_scale=0.05,  # Flexibility of trend changes
        seasonality_mode="multiplicative",  # Better for traffic patterns
    )

    # Add custom seasonality for business hours
    model.add_seasonality(name="business_hours", period=1, fourier_order=8)

    model.fit(data)

    future = model.make_future_dataframe(periods=periods, freq=freq)
    forecast = model.predict(future)

    return {
        "forecast": forecast[["ds", "yhat", "yhat_lower", "yhat_upper"]].tail(periods),
        "components": model.plot_components(forecast),
        "changepoints": model.changepoints.tolist(),
    }


def detect_capacity_breach(forecast_df: pd.DataFrame, threshold: float) -> list:
    """Find when forecasted value will exceed capacity threshold."""
    breaches = forecast_df[forecast_df["yhat"] > threshold]
    if len(breaches) > 0:
        first_breach = breaches.iloc[0]
        return {
            "will_breach": True,
            "first_breach_time": first_breach["ds"],
            "predicted_value": first_breach["yhat"],
            "threshold": threshold,
            "hours_until_breach": (first_breach["ds"] - pd.Timestamp.now()).total_seconds() / 3600,
        }
    return {"will_breach": False}
LSTM for Time-Series ▼

When to Use LSTM

LSTM captures complex non-linear patterns that ARIMA and Prophet miss. Use when: multiple correlated metrics (multivariate), non-linear relationships, or enough training data (10K+ data points).

"""LSTM for multivariate time-series forecasting."""
import torch
import torch.nn as nn
import numpy as np
from torch.utils.data import DataLoader, TensorDataset


class LSTMForecaster(nn.Module):
    """LSTM model for time-series forecasting."""

    def __init__(self, input_dim: int, hidden_dim: int = 64,
                 num_layers: int = 2, output_dim: int = 1):
        super().__init__()
        self.lstm = nn.LSTM(input_dim, hidden_dim, num_layers,
                            batch_first=True, dropout=0.2)
        self.fc = nn.Linear(hidden_dim, output_dim)

    def forward(self, x):
        # x shape: (batch, sequence_length, input_dim)
        lstm_out, _ = self.lstm(x)
        # Use last time step output
        last_step = lstm_out[:, -1, :]
        return self.fc(last_step)


def create_sequences(data: np.ndarray, window: int = 24) -> tuple:
    """Create sliding window sequences for LSTM training."""
    X, y = [], []
    for i in range(len(data) - window):
        X.append(data[i:i + window])
        y.append(data[i + window, 0])  # Predict first feature (e.g., request count)
    return np.array(X), np.array(y)


def train_lstm(data: np.ndarray, window: int = 24,
               epochs: int = 50, lr: float = 0.001) -> LSTMForecaster:
    """
    Train LSTM on multivariate time-series data.

    Args:
        data: shape (timesteps, features) e.g., [requests, cpu, memory, latency]
        window: lookback window in time steps
    """
    # Normalize
    mean, std = data.mean(axis=0), data.std(axis=0)
    normalized = (data - mean) / (std + 1e-8)

    X, y = create_sequences(normalized, window)

    # Train/val split
    split = int(len(X) * 0.8)
    X_train, X_val = X[:split], X[split:]
    y_train, y_val = y[:split], y[split:]

    # DataLoaders
    train_ds = TensorDataset(torch.FloatTensor(X_train), torch.FloatTensor(y_train))
    train_dl = DataLoader(train_ds, batch_size=32, shuffle=True)

    model = LSTMForecaster(input_dim=data.shape[1])
    optimizer = torch.optim.Adam(model.parameters(), lr=lr)
    criterion = nn.MSELoss()

    for epoch in range(epochs):
        model.train()
        total_loss = 0
        for X_batch, y_batch in train_dl:
            optimizer.zero_grad()
            pred = model(X_batch).squeeze()
            loss = criterion(pred, y_batch)
            loss.backward()
            optimizer.step()
            total_loss += loss.item()

    return model

2. Anomaly Detection

Anomaly Detection for Production Metrics ▼

Why Static Thresholds Fail

Setting "alert if CPU > 80%" fails because: traffic varies by time of day (80% at 2pm is normal, 80% at 3am is not), different services have different baselines, and gradual degradation is missed until it crosses the threshold. ML-based anomaly detection adapts to context.

Isolation Forest ▼

How It Works

Isolation Forest isolates anomalies through random partitioning. Anomalies are "few and different" — they get isolated in fewer random splits than normal points. No need to model the normal distribution.

"""Isolation Forest for real-time anomaly detection."""
from sklearn.ensemble import IsolationForest
from sklearn.preprocessing import StandardScaler
import numpy as np
import pandas as pd


class MetricAnomalyDetector:
    """Detects anomalies in production metrics using Isolation Forest."""

    def __init__(self, contamination: float = 0.05):
        """
        Args:
            contamination: Expected proportion of anomalies (0.01-0.1).
                          Lower = fewer alerts, higher precision.
        """
        self.model = IsolationForest(
            n_estimators=200,
            contamination=contamination,
            max_samples="auto",
            random_state=42,
            n_jobs=-1,
        )
        self.scaler = StandardScaler()
        self.is_fitted = False

    def fit(self, historical_data: pd.DataFrame):
        """Train on historical normal metrics."""
        X = self.scaler.fit_transform(historical_data)
        self.model.fit(X)
        self.is_fitted = True

    def detect(self, current_metrics: pd.DataFrame) -> pd.DataFrame:
        """Score current metrics. Returns DataFrame with anomaly labels and scores."""
        X = self.scaler.transform(current_metrics)
        scores = self.model.decision_function(X)  # Lower = more anomalous
        labels = self.model.predict(X)              # -1 = anomaly, 1 = normal

        result = current_metrics.copy()
        result["anomaly_score"] = -scores  # Invert so higher = more anomalous
        result["is_anomaly"] = labels == -1
        return result

    def detect_with_context(self, metrics: dict, service: str) -> dict:
        """Detect anomaly and provide context for the AI agent."""
        df = pd.DataFrame([metrics])
        result = self.detect(df)

        if result["is_anomaly"].iloc[0]:
            # Identify which features contribute most to anomaly
            feature_scores = {}
            for col in df.columns:
                single = df[[col]].copy()
                for other in df.columns:
                    if other != col:
                        single[other] = 0  # Zero out other features
                single_scaled = self.scaler.transform(single)
                feature_scores[col] = -self.model.decision_function(single_scaled)[0]

            top_contributors = sorted(feature_scores.items(), key=lambda x: x[1], reverse=True)[:3]

            return {
                "is_anomaly": True,
                "anomaly_score": float(result["anomaly_score"].iloc[0]),
                "service": service,
                "top_contributors": [
                    {"metric": k, "anomaly_contribution": round(v, 3)}
                    for k, v in top_contributors
                ],
                "raw_metrics": metrics,
            }

        return {"is_anomaly": False, "service": service}

Autoencoder-Based Anomaly Detection ▼

Intuition

Train an autoencoder to reconstruct normal metrics. When it sees anomalous data, reconstruction error spikes. The error magnitude tells you how anomalous the data is.

"""Autoencoder for anomaly detection in multivariate metrics."""
import torch
import torch.nn as nn
import numpy as np


class MetricAutoencoder(nn.Module):
    """Autoencoder that learns to reconstruct normal metric patterns."""

    def __init__(self, input_dim: int, encoding_dim: int = 8):
        super().__init__()
        self.encoder = nn.Sequential(
            nn.Linear(input_dim, 32),
            nn.ReLU(),
            nn.Linear(32, 16),
            nn.ReLU(),
            nn.Linear(16, encoding_dim),
        )
        self.decoder = nn.Sequential(
            nn.Linear(encoding_dim, 16),
            nn.ReLU(),
            nn.Linear(16, 32),
            nn.ReLU(),
            nn.Linear(32, input_dim),
        )

    def forward(self, x):
        encoded = self.encoder(x)
        decoded = self.decoder(encoded)
        return decoded


class AutoencoderAnomalyDetector:
    """Detects anomalies via reconstruction error."""

    def __init__(self, input_dim: int, threshold_percentile: float = 95):
        self.model = MetricAutoencoder(input_dim)
        self.threshold_percentile = threshold_percentile
        self.threshold = None

    def train(self, normal_data: np.ndarray, epochs: int = 100, lr: float = 0.001):
        """Train on data known to be normal."""
        tensor = torch.FloatTensor(normal_data)
        optimizer = torch.optim.Adam(self.model.parameters(), lr=lr)
        criterion = nn.MSELoss()

        self.model.train()
        for epoch in range(epochs):
            optimizer.zero_grad()
            reconstructed = self.model(tensor)
            loss = criterion(reconstructed, tensor)
            loss.backward()
            optimizer.step()

        # Set threshold from training data reconstruction errors
        self.model.eval()
        with torch.no_grad():
            recon = self.model(tensor)
            errors = torch.mean((tensor - recon) ** 2, dim=1).numpy()
            self.threshold = np.percentile(errors, self.threshold_percentile)

    def detect(self, data: np.ndarray) -> dict:
        """Detect anomalies in new data."""
        self.model.eval()
        with torch.no_grad():
            tensor = torch.FloatTensor(data)
            recon = self.model(tensor)
            errors = torch.mean((tensor - recon) ** 2, dim=1).numpy()

        return {
            "reconstruction_errors": errors.tolist(),
            "threshold": self.threshold,
            "is_anomaly": (errors > self.threshold).tolist(),
            "anomaly_scores": (errors / self.threshold).tolist(),  # >1 = anomalous
        }

3. Statistical Modeling for Operations

Change-Point Detection ▼

Why Change-Point Detection

Deployments, config changes, and infrastructure events cause distribution shifts in metrics. Change-point detection finds when a metric's behavior changed, which correlates with root cause.

"""Change-point detection for deployment impact analysis."""
import numpy as np
from scipy import stats


def cusum_detect(data: np.ndarray, threshold: float = 5.0,
                 drift: float = 0.5) -> list:
    """
    CUSUM (Cumulative Sum) change-point detection.
    Detects shifts in mean level of a time series.

    Args:
        data: Time series values
        threshold: Decision threshold (higher = fewer detections)
        drift: Allowance for natural variation
    """
    mean = np.mean(data[:50])  # Baseline from first 50 points
    std = np.std(data[:50])
    if std == 0:
        std = 1e-8

    normalized = (data - mean) / std

    s_pos, s_neg = 0, 0
    change_points = []

    for i, x in enumerate(normalized):
        s_pos = max(0, s_pos + x - drift)
        s_neg = max(0, s_neg - x - drift)

        if s_pos > threshold or s_neg > threshold:
            change_points.append({
                "index": i,
                "direction": "increase" if s_pos > threshold else "decrease",
                "magnitude": max(s_pos, s_neg),
            })
            s_pos, s_neg = 0, 0  # Reset after detection

    return change_points


def correlate_with_deployments(change_points: list, deployments: list,
                                window_minutes: int = 10) -> list:
    """Match detected change points with recent deployments."""
    correlated = []
    for cp in change_points:
        for deploy in deployments:
            time_diff = abs(cp["timestamp"] - deploy["timestamp"]).total_seconds() / 60
            if time_diff < window_minutes:
                correlated.append({
                    "change_point": cp,
                    "deployment": deploy,
                    "time_diff_minutes": time_diff,
                    "likely_cause": True,
                })
    return correlated

5. Feature Engineering for Production Data

Common Features from Metrics and Logs ▼ 
"""Feature engineering for production metrics."""
import numpy as np
import pandas as pd


def engineer_metric_features(series: pd.Series, window: int = 60) -> pd.DataFrame:
    """Create features from a raw metric time series.

    Args:
        series: Raw metric values (e.g., request_count per minute)
        window: Rolling window size in data points
    """
    features = pd.DataFrame(index=series.index)

    # Rolling statistics
    features["rolling_mean"] = series.rolling(window).mean()
    features["rolling_std"] = series.rolling(window).std()
    features["rolling_min"] = series.rolling(window).min()
    features["rolling_max"] = series.rolling(window).max()

    # Percentiles
    features["rolling_p50"] = series.rolling(window).quantile(0.5)
    features["rolling_p95"] = series.rolling(window).quantile(0.95)
    features["rolling_p99"] = series.rolling(window).quantile(0.99)

    # Rate of change
    features["rate_of_change"] = series.pct_change(periods=5)
    features["acceleration"] = features["rate_of_change"].diff()

    # Seasonality features
    if hasattr(series.index, 'hour'):
        features["hour_of_day"] = series.index.hour
        features["day_of_week"] = series.index.dayofweek
        features["is_business_hours"] = features["hour_of_day"].between(9, 17).astype(int)
        features["is_weekend"] = (features["day_of_week"] >= 5).astype(int)

    # Z-score (how many std devs from rolling mean)
    features["z_score"] = (series - features["rolling_mean"]) / (features["rolling_std"] + 1e-8)

    # Deployment features (if deployment timestamps available)
    features["minutes_since_deploy"] = np.nan  # Fill from deployment log

    return features.dropna()

Drift Detection

"""Model drift detection for production ML models."""
from scipy import stats
import numpy as np


def population_stability_index(expected: np.ndarray, actual: np.ndarray,
                                bins: int = 10) -> float:
    """
    Calculate PSI to detect distribution shift.
    PSI < 0.1: no shift. PSI 0.1-0.25: moderate shift. PSI > 0.25: significant shift.
    """
    breakpoints = np.linspace(min(expected.min(), actual.min()),
                              max(expected.max(), actual.max()), bins + 1)

    expected_pct = np.histogram(expected, breakpoints)[0] / len(expected)
    actual_pct = np.histogram(actual, breakpoints)[0] / len(actual)

    # Avoid division by zero
    expected_pct = np.clip(expected_pct, 0.001, None)
    actual_pct = np.clip(actual_pct, 0.001, None)

    psi = np.sum((actual_pct - expected_pct) * np.log(actual_pct / expected_pct))
    return float(psi)


def should_retrain(training_data: np.ndarray, recent_data: np.ndarray) -> dict:
    """Determine if a model needs retraining."""
    psi = population_stability_index(training_data, recent_data)
    ks_stat, ks_pvalue = stats.ks_2samp(training_data, recent_data)

    return {
        "psi": round(psi, 4),
        "ks_statistic": round(ks_stat, 4),
        "ks_pvalue": round(ks_pvalue, 4),
        "needs_retrain": psi > 0.2 or ks_pvalue < 0.01,
        "severity": "high" if psi > 0.25 else "medium" if psi > 0.1 else "low",
    }

7. Interview Prep

Common Questions & Flashcards ▼

"How would you build an anomaly detection system for API latency?"

Answer framework: (1) Collect historical latency data (P50, P95, P99 per minute). (2) Feature engineering: rolling stats, z-score, rate of change, hour-of-day seasonality. (3) Train Isolation Forest on 30 days of "normal" data. (4) Real-time scoring: every minute, compute features and score. (5) Alert if anomaly score > threshold. (6) Feed anomaly into AI agent for diagnosis. Key detail: the threshold depends on acceptable false-positive rate — start with contamination=0.03 (3% false positive) and tune based on ops team feedback.

Q: Why use Isolation Forest over Z-score for anomaly detection in production?
A: Z-score assumes normal distribution and works on single metrics. Production metrics are often multivariate (CPU+memory+latency correlated) and non-Gaussian (heavy tails, bimodal from traffic patterns). Isolation Forest handles multivariate, non-parametric data natively. Also handles the "normal at 2pm but anomalous at 3am" problem through feature engineering (hour_of_day as input feature).
Q: How do you unify classical ML with AI agents?
A: Classical ML models (anomaly detection, forecasting) run continuously and serve as tools the AI agent can call. The ML model answers "is this anomalous?" (classification) and "what will happen?" (forecasting). The LLM agent answers "why is this happening?" (reasoning) and "what should we do?" (action planning). Architecture: ML models expose tool interfaces (function calling / MCP), agent orchestrates investigation using both ML tools and production tools (Splunk, Grafana).
Q: What is PSI and when do you retrain a model?
A: PSI (Population Stability Index) measures distribution shift between training data and production data. PSI < 0.1 = stable, 0.1-0.25 = moderate drift, > 0.25 = significant drift (retrain). Also use KS test (p-value < 0.01 = significant shift). Retrain triggers: PSI > 0.2, prediction accuracy drops > 5%, or scheduled (weekly/monthly for fast-changing environments).
Q: ARIMA vs Prophet vs LSTM — when to use each?
A: ARIMA: single metric, short-term forecast, small data, interpretable. Prophet: capacity planning, business metrics with known seasonality, handles missing data, easy to use. LSTM: multivariate (CPU+memory+latency together), complex non-linear patterns, need 10K+ data points. For ops: start with Prophet for capacity planning, Isolation Forest for anomaly detection. Graduate to LSTM only if Prophet's accuracy is insufficient.
Q: What is CUSUM and why is it useful for deployment monitoring?
A: CUSUM (Cumulative Sum) detects shifts in the mean level of a time series. It accumulates deviations from a baseline — small drifts that are invisible in individual data points become obvious when accumulated. Useful for deployments because: it detects gradual degradation (not just spike alerts), identifies the exact timestamp of the shift (correlate with deploy time), and works with minimal tuning (threshold + drift parameters).

8. Quiz

1. Your anomaly detector flags CPU at 85% as anomalous at 3am but not at 2pm. How?

Answer: By including hour_of_day and is_business_hours as features. The model learns that 85% CPU at 2pm is within the normal distribution for business hours, but 85% at 3am (when traffic is typically 20% of peak) is highly anomalous. This is why feature engineering with temporal context is critical for ops anomaly detection.

2. Your Prophet forecast says capacity will breach in 6 hours. The AI agent calls the forecast tool. What should it do next?

Answer: (1) Verify with current metrics (is usage already trending up?). (2) Check if auto-scaling is configured and will handle it. (3) If not, propose proactive scaling (risk=MEDIUM). (4) Check deployment schedule (is a known traffic event coming?). (5) Notify the on-call team with the forecast and proposed action. This shows the agent reasoning about the ML output, not blindly acting on it.

3. You're choosing between Isolation Forest and an autoencoder for anomaly detection. What factors decide?

Answer: Isolation Forest: fewer features (<20), smaller dataset, need fast training, interpretability matters (can explain via feature contributions). Autoencoder: many features (>50), large dataset (100K+), complex non-linear correlations, subtle anomalies that IF misses. For most ops use cases, start with Isolation Forest — it's simpler, faster, and good enough for 90% of cases.
