Design: AI Content Moderation Pipeline

Examples: OpenAI Moderation API, Perspective API, Trust & Safety at Meta/TikTok

Difficulty: Hard | Time: 45-60 minutes

1. Requirements Clarification

Functional Requirements ▼
  • Multi-modal content classification — text, images, video, audio
  • Category detection — hate speech, violence, sexual content, self-harm, misinformation, spam
  • Real-time input moderation — block harmful prompts before they reach the LLM
  • Output moderation — filter LLM responses before showing to user
  • Configurable policies — different thresholds per platform/market/use-case
  • Human-in-the-loop — escalation for edge cases, appeal workflow
  • Explainability — why content was flagged (for appeals and auditing)
Non-Functional Requirements ▼
  • Latency: P95 < 100ms for text, < 500ms for images (inline with user request)
  • Throughput: 500K+ content items/minute at peak
  • Precision: > 95% precision (minimize false positives that censor valid content)
  • Recall: > 99% for high-severity categories (CSAM, violence)
  • Multi-language: Support 50+ languages
  • Regulatory compliance: GDPR, DSA (EU Digital Services Act), local laws

2. Scale & Capacity Estimation

Back-of-Envelope Math ▼
Content Volume (social platform scale):
- 500M posts/day (text + image + video)
- 80% text-only, 15% image, 5% video
- Peak: ~10K items/second

For LLM guardrails (API platform):
- 100M API calls/day
- Each call: input moderation + output moderation = 2 checks
- Peak: ~4K checks/second

Model Inference:
- Text classifier: ~5ms per item (lightweight BERT-class)
- Image classifier: ~50ms per item (ViT/CLIP)
- LLM-based nuance check: ~200ms (for edge cases only, ~5% of traffic)

Human Review:
- 2-5% of content escalated to human review
- At 500M/day = 10-25M items/day for humans
- 1 reviewer handles ~500 items/day = 20K-50K reviewers needed (or heavy pre-filtering)

3. Multi-Tier Classification Architecture

Cascading Classifier Design ▼

Not every content item needs the same level of analysis. Use a cascade to balance speed and accuracy:

Tier Architecture

Tier Model Latency Traffic Purpose
1 - Fast Filter Keyword blocklist + regex < 1ms 100% Catch obvious violations fast
2 - ML Classifier Fine-tuned BERT/DistilBERT ~5ms ~95% Multi-label classification
3 - LLM Judge GPT-4 / Claude with policy prompt ~200ms ~5% Nuanced/ambiguous cases
4 - Human Review Human reviewer + tooling Minutes-Hours ~1% Appeals, policy edge cases

Code Sample: Cascading Moderation Pipeline

from dataclasses import dataclass, field
from enum import Enum

class Severity(Enum):
    SAFE = "safe"
    LOW = "low"
    MEDIUM = "medium"
    HIGH = "high"
    CRITICAL = "critical"  # CSAM, imminent violence

class Action(Enum):
    ALLOW = "allow"
    FLAG = "flag"           # Show but flag for review
    BLUR = "blur"           # Show with warning
    BLOCK = "block"         # Remove content
    ESCALATE = "escalate"   # Human review required

@dataclass
class ModerationResult:
    action: Action
    categories: dict[str, float]   # category -> confidence
    severity: Severity
    explanation: str
    tier_reached: int              # Which tier made the decision
    latency_ms: float

class CascadingModerator:
    """Multi-tier content moderation pipeline."""

    def __init__(self, keyword_filter, ml_classifier,
                 llm_judge, policy_config):
        self.keyword = keyword_filter
        self.ml = ml_classifier
        self.llm = llm_judge
        self.policy = policy_config

    async def moderate(self, content: str,
                       content_type: str = "text") -> ModerationResult:
        import time
        start = time.monotonic()

        # Tier 1: Keyword/regex blocklist (<1ms)
        keyword_match = self.keyword.check(content)
        if keyword_match.is_critical:
            return ModerationResult(
                action=Action.BLOCK,
                categories=keyword_match.categories,
                severity=Severity.CRITICAL,
                explanation=f"Matched blocklist: {keyword_match.pattern}",
                tier_reached=1,
                latency_ms=(time.monotonic() - start) * 1000,
            )

        # Tier 2: ML classifier (~5ms)
        ml_result = await self.ml.classify(content)
        max_category = max(ml_result.scores, key=ml_result.scores.get)
        max_score = ml_result.scores[max_category]

        # High confidence -> decide immediately
        if max_score > 0.95:
            action = self.policy.get_action(max_category, max_score)
            return ModerationResult(
                action=action,
                categories=ml_result.scores,
                severity=self._score_to_severity(max_score),
                explanation=f"ML classifier: {max_category} ({max_score:.2f})",
                tier_reached=2,
                latency_ms=(time.monotonic() - start) * 1000,
            )

        # Low confidence -> safe
        if max_score < 0.3:
            return ModerationResult(
                action=Action.ALLOW,
                categories=ml_result.scores,
                severity=Severity.SAFE,
                explanation="Below threshold",
                tier_reached=2,
                latency_ms=(time.monotonic() - start) * 1000,
            )

        # Tier 3: Ambiguous zone (0.3-0.95) -> LLM judge
        llm_result = await self.llm.judge(
            content=content,
            ml_categories=ml_result.scores,
            policy=self.policy.get_rules(max_category),
        )

        return ModerationResult(
            action=llm_result.action,
            categories=llm_result.categories,
            severity=llm_result.severity,
            explanation=llm_result.explanation,
            tier_reached=3,
            latency_ms=(time.monotonic() - start) * 1000,
        )

    def _score_to_severity(self, score: float) -> Severity:
        if score > 0.99: return Severity.CRITICAL
        if score > 0.95: return Severity.HIGH
        if score > 0.8: return Severity.MEDIUM
        return Severity.LOW

4. LLM Input/Output Guardrails

Protecting LLM Applications ▼

Input Guardrails (Pre-LLM)

  • Prompt injection detection: Classify if user input attempts to override system prompt
  • Toxicity filter: Block abusive/hateful user messages
  • PII detection: Redact personal information before sending to LLM
  • Topic guardrails: Reject out-of-scope queries (e.g., medical advice for a cooking bot)

Output Guardrails (Post-LLM)

  • Toxicity check: Ensure model response isn't harmful
  • Factuality check: Cross-reference claims against retrieved sources
  • PII leak detection: Catch if model reveals PII from training data
  • Policy compliance: Verify response doesn't violate brand guidelines

class LLMGuardrails:
    """Input/output guardrails for LLM applications."""

    def __init__(self, input_moderator, output_moderator,
                 pii_detector, injection_detector):
        self.input_mod = input_moderator
        self.output_mod = output_moderator
        self.pii = pii_detector
        self.injection = injection_detector

    async def check_input(self, user_message: str) -> dict:
        """Pre-LLM guardrails. Returns sanitized message or block signal."""
        # Parallel checks for speed
        import asyncio
        injection, toxicity, pii_scan = await asyncio.gather(
            self.injection.detect(user_message),
            self.input_mod.classify(user_message),
            self.pii.scan(user_message),
        )

        if injection.is_injection:
            return {"action": "block", "reason": "Prompt injection detected"}

        if toxicity.scores.get("hate", 0) > 0.9:
            return {"action": "block", "reason": "Harmful content"}

        # Redact PII
        sanitized = user_message
        if pii_scan.entities:
            sanitized = self.pii.redact(user_message, pii_scan.entities)

        return {"action": "pass", "sanitized_message": sanitized}

    async def check_output(self, response: str,
                           context_sources: list[str]) -> dict:
        """Post-LLM guardrails."""
        import asyncio
        toxicity, pii_leak = await asyncio.gather(
            self.output_mod.classify(response),
            self.pii.scan(response),
        )

        if toxicity.max_score > 0.8:
            return {"action": "block", "reason": "Harmful response generated"}

        if pii_leak.entities:
            return {"action": "redact", "clean_response":
                    self.pii.redact(response, pii_leak.entities)}

        return {"action": "pass", "response": response}

5. Multi-Modal Moderation

Image, Video & Audio ▼

Image Moderation Pipeline

  • Perceptual hashing (pHash): Match against known harmful image database (PhotoDNA for CSAM)
  • CLIP-based classification: Zero-shot or fine-tuned CLIP for category detection
  • OCR + text moderation: Extract text from images, run through text pipeline
  • NSFW classifier: Dedicated model for nudity/sexual content detection

Video Moderation

  • Sample keyframes (1 per second for short videos, 1 per 5s for long)
  • Run image moderation on each keyframe
  • Audio transcription (Whisper) → text moderation
  • Scene-level aggregation: flag video if any segment exceeds threshold

Cross-Modal Attacks

Staff-Level Insight: Adversaries exploit modality gaps. Text says "beautiful sunset" but image is violent. Or text in an image bypasses text filters. Multi-modal moderation must fuse signals across modalities, not treat them independently. CLIP-based joint embeddings help, but dedicated fusion models are needed for production.

7. Human-in-the-Loop & Active Learning

Review Workflows & Model Improvement ▼

Review Queue Prioritization

  • Severity-first: CSAM and imminent violence always top priority
  • Uncertainty sampling: Items where ML confidence is 0.4-0.6 (most informative for retraining)
  • High-reach content: Posts from accounts with large followings get faster review
  • Appeal queue: User-contested decisions within SLA

Active Learning Loop

  • Human decisions become training labels for next model iteration
  • Focus labeling budget on ambiguous cases (uncertainty sampling)
  • Weekly model retrain with new labels + evaluation on held-out test set
  • A/B test new model on 5% traffic before full rollout

Reviewer Wellness

Important: Content reviewers see the worst content on the internet. System design must include: exposure limits (no more than 4 hours/day on severe content), auto-blurring with opt-in to view, rotation across severity levels, mandatory breaks, and access to mental health support. This is a staff-level consideration that shows maturity.

9. Staff-Level Discussion Points

Precision vs Recall Tradeoff & Policy Design ▼

Precision vs Recall: Context Matters

  • CSAM / imminent violence: Optimize for recall (99.9%+). False positives are acceptable — the cost of missing one is catastrophic.
  • Hate speech / misinformation: Balance precision and recall. High false positives erode user trust and create censorship concerns.
  • Spam: Optimize for precision. Blocking a legitimate post is worse than letting some spam through.

Policy-as-Code

Moderation policies should be configurable, not hardcoded:

  • Different thresholds per market (EU DSA requirements vs US)
  • Different rules per content type (user post vs comment vs DM)
  • Version-controlled policy configs with audit trail
  • A/B testing policy changes before global rollout

The Evals Problem

  • Content moderation is inherently subjective — even humans disagree (inter-rater agreement ~70-80% for hate speech)
  • Ground truth labels shift as social norms change
  • Must maintain per-category, per-language eval sets and refresh quarterly
  • Cohen's Kappa or Krippendorff's Alpha for measuring agreement

10. Interview Tips & Follow-ups

How to Ace This Problem ▼

What Interviewers Look For

  • Cascade thinking: Not one model for everything — tiered approach with cost/latency awareness
  • Precision/recall tradeoff awareness: Different categories need different operating points
  • Human-in-the-loop: ML alone can't solve moderation; show the full human+AI system
  • Adversarial mindset: How will users try to bypass your system?

Common Follow-ups

  • "How do you handle content in a language your model doesn't support well?"
  • "A new meme format is being used for hate speech. How fast can your system adapt?"
  • "How do you balance free speech vs safety? Who decides the policy?"
  • "How do you evaluate and prevent bias in your moderation model?"
  • "How does your system handle context-dependent moderation?" (e.g., 'kill' in gaming vs threat)

11. Active Recall Quiz

Test Your Understanding (6 Questions) ▼
Q1: Why use a cascading classifier instead of one powerful model for all content?
Show Answer▼

Cost and latency. At 500M items/day, running an LLM on everything is prohibitively expensive. Keyword filters catch ~5% instantly (<1ms), ML classifiers handle ~90% in 5ms, and only ~5% ambiguous cases need the expensive LLM judge. This keeps average latency low and cost manageable.

Q2: When should you optimize for recall over precision in content moderation?
Show Answer▼

For high-severity categories like CSAM and imminent violence — the cost of missing one harmful item is catastrophic (legal liability, real harm). False positives (over-blocking) are acceptable here and can be resolved through human review and appeals.

Q3: What is a cross-modal attack and how do you defend against it?
Show Answer▼

Adversary uses one modality to bypass filters in another — e.g., harmful text embedded in an image (bypasses text filters), or benign caption with violent image. Defense: multi-modal fusion models that consider all modalities together, OCR on images, and cross-modal consistency checks.

Q4: How does active learning improve moderation models over time?
Show Answer▼

Route ambiguous cases (ML confidence 0.4-0.6) to human reviewers. These are the most informative training examples. Human decisions become labels for the next model retrain. This focuses labeling budget on the decision boundary where the model struggles most, maximizing improvement per label.

Q5: Why is content moderation evaluation harder than typical ML evaluation?
Show Answer▼

Moderation is inherently subjective — even humans only agree 70-80% on hate speech. Social norms shift (yesterday's acceptable is today's harmful). Adversaries constantly evolve tactics. Need per-category, per-language eval sets refreshed quarterly, with inter-rater agreement metrics (Cohen's Kappa) as a ceiling on model performance.

Q6: How do you design guardrails for LLM output moderation specifically?
Show Answer▼

"Guardrails sandwich": input guards (prompt injection, toxicity, PII detection) before the LLM, output guards (toxicity, factuality, PII leak, policy compliance) after. Run checks in parallel for speed. On output violation: either block with fallback response, redact PII, or re-prompt with tighter constraints.
