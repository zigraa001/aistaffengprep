Design: Enterprise Knowledge Assistant

Conversational Q&A over Confluence, Slack, JIRA, Google Drive

Difficulty: Hard | Time: 45-60 minutes

1. Requirements Clarification

Functional Requirements ▼
  • Conversational Q&A over enterprise knowledge bases (Confluence, Slack, JIRA, Google Drive)
  • Multi-turn conversations with context retention across messages
  • Cited answers — every response links back to source documents
  • Role-based access control — respects existing document permissions
  • Feedback loop — thumbs up/down, flag incorrect answers
  • Structured data queries — "How many P0 bugs were filed this sprint?" via SQL agent
  • Escalation — route to human expert when confidence is low
Non-Functional Requirements ▼
  • SOC2 compliance — data encryption, audit logs, no data leaves tenant boundary
  • Latency: P95 < 3 seconds for response
  • Concurrency: 10K concurrent users
  • Data freshness: Incremental sync within 30 minutes
  • PII handling: Detect and redact PII before sending to LLM

2. Scale & Capacity Estimation

Back-of-Envelope Math ▼
Data Sources (mid-size enterprise, ~5K employees):
- Confluence: 500K pages
- Slack: 2M messages/month (6 months history = 12M messages)
- JIRA: 200K tickets
- Google Drive: 1M documents
- Total: ~14M source items

After Chunking:
- Confluence: 500K × 8 chunks = 4M chunks
- Slack: Thread-based grouping → 2M thread chunks
- JIRA: 200K tickets (1 chunk each, metadata-heavy)
- Drive: 1M × 5 chunks = 5M chunks
- Total: ~11M vectors

Query Load:
- 10K concurrent users, avg 5 queries/hour each
- Peak: 50K queries/hour ≈ ~14 QPS
- Each query: multi-turn context (avg 3 turns) + retrieval + generation
- Token budget per query: ~6K input + ~800 output

Monthly Cost:
- ~2M queries/month × 6.8K tokens × $3/1M = ~$40K LLM
- Vector DB: ~$1.5K/month
- Connectors + compute: ~$3K/month
- Total: ~$45K/month

Schema Normalization

from dataclasses import dataclass, field
from datetime import datetime
from enum import Enum

class SourceType(Enum):
    CONFLUENCE = "confluence"
    SLACK = "slack"
    JIRA = "jira"
    GOOGLE_DRIVE = "google_drive"

@dataclass
class NormalizedDocument:
    """Unified document representation across all sources."""
    source_id: str            # Original ID in source system
    source_type: SourceType
    title: str
    content: str              # Cleaned text content
    url: str                  # Deep link back to source
    author: str
    created_at: datetime
    updated_at: datetime
    access_groups: list[str]  # ACL groups that can access this doc
    metadata: dict = field(default_factory=dict)  # Source-specific fields

    @property
    def global_id(self) -> str:
        return f"{self.source_type.value}:{self.source_id}"


class SlackConnector:
    """Incremental Slack sync with thread-aware chunking."""

    def __init__(self, client, acl_resolver):
        self.client = client
        self.acl = acl_resolver

    async def sync_channel(self, channel_id: str,
                           since: datetime) -> list[NormalizedDocument]:
        docs = []
        # Fetch messages since last sync
        messages = await self.client.conversations_history(
            channel=channel_id, oldest=since.timestamp()
        )

        # Group by thread
        threads = {}
        for msg in messages["messages"]:
            thread_ts = msg.get("thread_ts", msg["ts"])
            threads.setdefault(thread_ts, []).append(msg)

        for thread_ts, thread_msgs in threads.items():
            # Resolve channel ACL
            members = await self.acl.get_channel_members(channel_id)
            access_groups = [f"slack:channel:{channel_id}"]

            combined_text = "\n".join(
                f"{m.get('user', 'unknown')}: {m.get('text', '')}"
                for m in sorted(thread_msgs, key=lambda x: x["ts"])
            )

            docs.append(NormalizedDocument(
                source_id=f"{channel_id}:{thread_ts}",
                source_type=SourceType.SLACK,
                title=f"Slack thread in #{channel_id}",
                content=combined_text,
                url=f"https://slack.com/archives/{channel_id}/p{thread_ts.replace('.', '')}",
                author=thread_msgs[0].get("user", "unknown"),
                created_at=datetime.fromtimestamp(float(thread_ts)),
                updated_at=datetime.fromtimestamp(
                    float(thread_msgs[-1]["ts"])
                ),
                access_groups=access_groups,
            ))

        return docs

4. RAG Pipeline

Source-Aware Retrieval ▼

Per-Source Chunking Strategy

  • Confluence: Section-based chunking (H1/H2 boundaries), preserve table structure
  • Slack: Thread-level chunks with user attribution, skip bot messages
  • JIRA: Whole ticket as one chunk (title + description + comments), extract structured fields as metadata
  • Google Drive: Semantic chunking for docs, slide-level for presentations

Permission-Aware Filtering

At query time, resolve user's access groups and apply as vector DB filter:

class PermissionAwareRetriever:
    """Retriever that enforces document-level ACL."""

    def __init__(self, vector_db, acl_store, reranker):
        self.vector_db = vector_db
        self.acl_store = acl_store
        self.reranker = reranker

    async def retrieve(self, query: str, user_id: str,
                       top_k: int = 10) -> list[dict]:
        # Step 1: Resolve user's access groups across all sources
        user_groups = await self.acl_store.get_user_groups(user_id)
        # e.g., ["confluence:space:ENG", "slack:channel:C1234",
        #        "jira:project:PLAT", "gdrive:folder:shared-eng"]

        # Step 2: Query vector DB with ACL filter
        results = await self.vector_db.query(
            query_text=query,
            filter={
                "access_groups": {"$overlap": user_groups}
            },
            top_k=50,  # Over-fetch for reranking
        )

        # Step 3: Rerank with source diversity
        reranked = await self.reranker.rerank(
            query=query,
            documents=[r["text"] for r in results],
            top_k=top_k,
        )

        # Step 4: Ensure source diversity (at least 2 different sources)
        final = self._diversify_sources(
            [results[i] for i in reranked.indices], min_sources=2
        )

        return final[:top_k]

    def _diversify_sources(self, results, min_sources=2):
        """Ensure results come from multiple sources when possible."""
        sources_seen = set()
        diverse, remaining = [], []

        for r in results:
            src = r["metadata"]["source_type"]
            if src not in sources_seen:
                diverse.append(r)
                sources_seen.add(src)
            else:
                remaining.append(r)

        return diverse + remaining

Code Sample: Conversation Memory Manager

from dataclasses import dataclass, field
from datetime import datetime

@dataclass
class Message:
    role: str  # "user" or "assistant"
    content: str
    timestamp: datetime = field(default_factory=datetime.now)
    sources: list[dict] = field(default_factory=list)

class ConversationMemory:
    """Manages multi-turn context with sliding window + summary."""

    def __init__(self, llm_client, max_buffer=6, max_tokens=4000):
        self.llm = llm_client
        self.max_buffer = max_buffer
        self.max_tokens = max_tokens
        self.sessions: dict[str, list[Message]] = {}
        self.summaries: dict[str, str] = {}

    def add_message(self, session_id: str, message: Message):
        self.sessions.setdefault(session_id, []).append(message)

    async def get_context(self, session_id: str) -> list[dict]:
        """Build context window: summary + recent messages."""
        history = self.sessions.get(session_id, [])

        if len(history) <= self.max_buffer:
            return [{"role": m.role, "content": m.content} for m in history]

        # Summarize older messages
        older = history[:-self.max_buffer]
        recent = history[-self.max_buffer:]

        if older and session_id not in self.summaries:
            self.summaries[session_id] = await self._summarize(older)

        context = []
        if session_id in self.summaries:
            context.append({
                "role": "system",
                "content": f"Previous conversation summary: {self.summaries[session_id]}"
            })

        context.extend(
            {"role": m.role, "content": m.content} for m in recent
        )
        return context

    async def _summarize(self, messages: list[Message]) -> str:
        text = "\n".join(f"{m.role}: {m.content}" for m in messages)
        response = await self.llm.chat(messages=[{
            "role": "user",
            "content": (
                f"Summarize this conversation in 2-3 sentences, "
                f"preserving key facts and questions:\n\n{text}"
            ),
        }], temperature=0, max_tokens=200)
        return response.content

from enum import Enum
from dataclasses import dataclass

class Intent(Enum):
    DOCUMENT_QA = "document_qa"       # "What is our deployment process?"
    STRUCTURED_QUERY = "structured"   # "How many P0 bugs this sprint?"
    CLARIFICATION = "clarification"   # Ambiguous query
    CHITCHAT = "chitchat"             # "Hello", "Thanks"
    OUT_OF_SCOPE = "out_of_scope"     # "What's the weather?"

@dataclass
class RoutingDecision:
    intent: Intent
    confidence: float
    rewritten_query: str  # Self-contained version of query

class RouterAgent:
    def __init__(self, llm_client):
        self.llm = llm_client

    async def route(self, query: str,
                    conversation_context: list[dict]) -> RoutingDecision:
        response = await self.llm.chat(
            messages=[
                {"role": "system", "content": ROUTER_PROMPT},
                *conversation_context,
                {"role": "user", "content": query},
            ],
            temperature=0,
            response_format={"type": "json_object"},
        )

        result = json.loads(response.content)
        return RoutingDecision(
            intent=Intent(result["intent"]),
            confidence=result["confidence"],
            rewritten_query=result["rewritten_query"],

ROUTER_PROMPT = """You are a query router for an enterprise knowledge assistant.
Classify the user query into one of these intents:
- document_qa: Questions answerable from documents (Confluence, Drive, Slack threads)
- structured: Questions requiring data queries (JIRA stats, metrics, counts)

- chitchat: Greeting, thanks, or social interaction

7. Access Control & Security

ACL Propagation & SOC2 Compliance ▼

ACL Architecture

  • Index-time ACL tagging: Each chunk stores access_groups[] from source system
  • Query-time enforcement: Vector DB filter on user's resolved groups
  • Real-time ACL sync: Webhooks from Confluence/Slack/Drive update ACL tags within minutes
  • Deny-by-default: If ACL resolution fails, return no results (never over-expose)

Security Layers

Layer Implementation
Encryption at rest AES-256 for vector DB and chunk store
Encryption in transit TLS 1.3 for all API calls including LLM provider
PII masking Presidio scan on chunks before LLM prompt
Audit logging Every query, retrieval, and response logged with user ID
Prompt injection defense Input sanitization + output validation + system prompt isolation
Data residency Self-hosted LLM option for regulated industries

9. Evaluation & Feedback Loop

Metrics, A/B Testing & Continuous Improvement ▼

Key Metrics

Metric Target How to Measure

Faithfulness > 0.90 RAGAS faithfulness (claims vs context)
User Satisfaction > 80% positive Thumbs up/down ratio

Feedback-Driven Improvement

  • Thumbs down pipeline: Flag → human review → add to eval set → fix retrieval or prompt
  • A/B testing: Test prompt variants, chunking strategies, reranker models on 10% traffic
  • Weekly eval runs: Run RAGAS on golden dataset (200+ Q&A pairs) after every change
  • Drift detection: Monitor embedding distribution shift; alert when retrieval quality degrades

Staff-Level Take: Start with Glean/buy for 80% of use cases. Build custom only when: (1) you need deep workflow integration (e.g., auto-creating JIRA tickets from answers), (2) compliance requires self-hosted LLM, or (3) the assistant is a core product differentiator, not internal tooling.

When to Add Fine-Tuning

  • Not day 1. Start with good retrieval + prompting.
  • Fine-tune retriever when eval shows relevant docs exist but aren't being retrieved (low recall despite good chunking)
  • Fine-tune generator when output format/tone is consistently wrong despite prompt engineering
  • Distill to smaller model when cost exceeds budget — use GPT-4 for training data, deploy fine-tuned GPT-3.5/Llama

13. Active Recall Quiz

Test Your Understanding (6 Questions) ▼
Q1: Why do you need different chunking strategies for Slack vs Confluence?
Show Answer▼

Slack is conversational (short messages, threads), so you chunk by thread to preserve context. Confluence is structured (pages, sections, tables), so you chunk by headings/sections to preserve document structure. One-size-fits-all chunking loses important structural cues from each source.

Q2: Explain query rewriting for multi-turn conversations and why it's better than sending full history.
Show Answer▼

Query rewriting transforms a context-dependent query ("What about its latency?") into a self-contained one ("What is the latency of the payment service?"). This is better because: (1) the retriever gets a focused query instead of noisy history, (2) fewer tokens sent to embedding model, (3) retrieval quality is higher since the query is unambiguous.

Q3: How does the router agent pattern differ from a single monolithic prompt?
Show Answer▼

Router classifies intent first, then dispatches to specialized agents (RAG, SQL, escalation). Each agent has focused instructions and tools. A monolithic prompt tries to handle everything — it's harder to optimize, debug, and extend. Router pattern also allows different models per agent (cheap for routing, powerful for generation).

Q4: What's the difference between index-time and query-time ACL enforcement, and why do you need both?
Show Answer▼

Index-time ACL tags chunks with access groups during ingestion. Query-time enforcement filters retrieval results by user's current groups. You need both because: index-time tags enable efficient DB-level filtering, while query-time checks handle permission changes since last index (e.g., user removed from a Confluence space).

Q5: When would you choose to build this system custom vs buying Glean?
Show Answer▼

Build custom when: (1) need deep workflow integration (auto-create tickets, trigger deployments), (2) compliance requires self-hosted LLM (healthcare, finance), (3) the assistant is a core product, not internal tool. Buy Glean when: fast time-to-value matters, broad connector coverage needed, and standard Q&A use case is sufficient.

Q6: How do you handle PII in an enterprise knowledge assistant pipeline?
Show Answer▼

Four-layer approach: (1) Pre-indexing scan with Presidio/Comprehend to redact or mask PII before embedding. (2) Query-time scan on retrieved chunks before LLM prompt. (3) Output filter on LLM response to catch any leaked PII. (4) Audit log all queries touching PII-flagged documents for compliance review.
