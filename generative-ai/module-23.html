1. Production Runtime Integration

Why Integration Is the Hard Part ▼

The Real Challenge

Building an LLM agent is easy. Connecting it to production systems safely is hard. Every integration needs:

  • Authentication: Scoped API keys, service accounts, OAuth tokens
  • Rate limiting: Don't DDoS your own monitoring systems
  • Error handling: Graceful degradation when an API is down
  • Data filtering: Don't send sensitive data (PII, credentials) to LLM providers

"""Production tool implementations for AI agents."""
import httpx
from datetime import datetime, timedelta
from typing import Optional


class PagerDutyTool:
    """Agent tool for PagerDuty alert management."""

    def __init__(self, api_key: str, base_url: str = "https://api.pagerduty.com"):
        self.client = httpx.AsyncClient(
            base_url=base_url,
            headers={"Authorization": f"Token token={api_key}",
                     "Content-Type": "application/json"},
            timeout=10.0,
        )

    async def get_incident(self, incident_id: str) -> dict:
        """Fetch incident details including timeline and assignments."""
        resp = await self.client.get(f"/incidents/{incident_id}")
        resp.raise_for_status()
        incident = resp.json()["incident"]
        return {
            "id": incident["id"],
            "title": incident["title"],
            "status": incident["status"],
            "urgency": incident["urgency"],
            "service": incident["service"]["summary"],
            "created_at": incident["created_at"],
            "assignments": [a["assignee"]["summary"] for a in incident.get("assignments", [])],
            "alert_count": incident.get("alert_counts", {}).get("all", 0),
        }

    async def get_recent_alerts(self, service_id: str, since_minutes: int = 30) -> list:
        """Get recent alerts for a service."""
        since = (datetime.utcnow() - timedelta(minutes=since_minutes)).isoformat() + "Z"
        resp = await self.client.get("/alerts", params={
            "service_ids[]": service_id, "since": since, "sort_by": "created_at:desc"
        })
        resp.raise_for_status()
        return [{"id": a["id"], "summary": a["summary"], "severity": a["severity"]["value"],
                 "created_at": a["created_at"]}
                for a in resp.json().get("alerts", [])]

    async def acknowledge_incident(self, incident_id: str, agent_id: str) -> dict:
        """Acknowledge an incident (agent takes ownership)."""
        resp = await self.client.put(f"/incidents/{incident_id}", json={
            "incident": {"type": "incident_reference", "status": "acknowledged"}
        })
        resp.raise_for_status()
        return {"status": "acknowledged", "by": agent_id}


class SplunkTool:
    """Agent tool for querying Splunk logs."""

    def __init__(self, base_url: str, token: str):
        self.client = httpx.AsyncClient(
            base_url=base_url,
            headers={"Authorization": f"Bearer {token}"},
            timeout=30.0,
        )

    async def search_logs(self, query: str, earliest: str = "-15m",
                          latest: str = "now", max_results: int = 100) -> dict:
        """Execute a Splunk search and return results."""
        search_query = f"search {query} | head {max_results}"
        resp = await self.client.post("/services/search/jobs", data={
            "search": search_query,
            "earliest_time": earliest,
            "latest_time": latest,
            "output_mode": "json",
            "exec_mode": "oneshot",
        })
        resp.raise_for_status()
        results = resp.json().get("results", [])
        return {
            "query": query,
            "result_count": len(results),
            "results": results[:max_results],
            "time_range": f"{earliest} to {latest}",
        }

    async def get_error_summary(self, service: str, minutes: int = 15) -> dict:
        """Get error log summary for a service."""
        query = f'index=production service="{service}" level=ERROR | stats count by message | sort -count'
        return await self.search_logs(query, earliest=f"-{minutes}m")


class GrafanaTool:
    """Agent tool for querying Grafana metrics."""

    def __init__(self, base_url: str, api_key: str):
        self.client = httpx.AsyncClient(
            base_url=base_url,
            headers={"Authorization": f"Bearer {api_key}"},
            timeout=15.0,
        )

    async def query_metric(self, query: str, start: str = "now-15m",
                           end: str = "now", step: str = "30s") -> dict:
        """Query a Prometheus metric via Grafana proxy."""
        resp = await self.client.get("/api/datasources/proxy/1/api/v1/query_range", params={
            "query": query, "start": start, "end": end, "step": step,
        })
        resp.raise_for_status()
        data = resp.json()["data"]["result"]
        return {
            "query": query,
            "series_count": len(data),
            "data": [{
                "labels": series["metric"],
                "values": [(ts, float(val)) for ts, val in series["values"][-10:]],
            } for series in data[:5]],
        }

    async def get_service_health(self, service: str) -> dict:
        """Get key health metrics for a service."""
        metrics = {}
        for name, query in [
            ("error_rate", f'rate(http_requests_total{{service="{service}",status=~"5.."}}[5m])'),
            ("latency_p99", f'histogram_quantile(0.99, rate(http_request_duration_seconds_bucket{{service="{service}"}}[5m]))'),
            ("cpu_usage", f'rate(container_cpu_usage_seconds_total{{pod=~"{service}.*"}}[5m])'),
            ("memory_usage", f'container_memory_usage_bytes{{pod=~"{service}.*"}}'),
        ]:
            try:
                result = await self.query_metric(query)
                if result["data"]:
                    latest_value = result["data"][0]["values"][-1][1] if result["data"][0]["values"] else None
                    metrics[name] = latest_value
            except Exception:
                metrics[name] = None
        return {"service": service, "metrics": metrics}

"""Diagnostic Agent: investigates production incidents."""
import asyncio
import json
from dataclasses import dataclass, field
from typing import Optional
from openai import AsyncOpenAI


@dataclass
class DiagnosticResult:
    root_cause: str
    confidence: float
    evidence: list[dict]
    suggested_remediation: str
    affected_services: list[str]
    timeline: list[dict]


class DiagnosticAgent:
    """Diagnoses production incidents using logs, metrics, and service topology."""

    def __init__(self, splunk: 'SplunkTool', grafana: 'GrafanaTool', llm_client: AsyncOpenAI):
        self.splunk = splunk
        self.grafana = grafana
        self.llm = llm_client
        self.system_prompt = """You are a production diagnostics agent. Given an alert and
investigation data (logs, metrics, service topology), identify the root cause.

Rules:
1. Always cite specific evidence (log lines, metric values, timestamps)
2. Assign a confidence score (0.0-1.0) based on evidence strength
3. If confidence < 0.6, explicitly say "insufficient evidence, recommend human investigation"
4. Never guess without evidence - say "unknown" rather than speculate
5. Consider common patterns: memory leaks, deployment regressions, dependency failures,
   configuration changes, traffic spikes, certificate expiry

Output JSON:
{
    "root_cause": "description of root cause",
    "confidence": 0.85,
    "evidence": [{"source": "logs|metrics|topology", "detail": "..."}],
    "suggested_remediation": "recommended fix",
    "affected_services": ["service1", "service2"]
}"""

    async def investigate(self, alert: dict) -> DiagnosticResult:
        """Run a full diagnostic investigation for an alert."""
        service = alert["service"]
        timeline = [{"ts": alert["created_at"], "event": f"Alert: {alert['title']}"}]

        # Phase 1: Parallel data gathering
        log_task = asyncio.create_task(self._gather_logs(service))
        metric_task = asyncio.create_task(self._gather_metrics(service))

        try:
            logs, metrics = await asyncio.wait_for(
                asyncio.gather(log_task, metric_task, return_exceptions=True),
                timeout=10.0,  # 10s budget for data gathering
            )
        except asyncio.TimeoutError:
            logs = {"error": "log query timed out"}
            metrics = {"error": "metric query timed out"}

        timeline.append({"ts": "now", "event": "Data gathering complete"})

        # Phase 2: LLM-powered diagnosis
        diagnosis_prompt = f"""Investigate this production alert:

Alert: {json.dumps(alert, indent=2)}

Log Analysis Results:
{json.dumps(logs, indent=2)}

Metric Analysis Results:
{json.dumps(metrics, indent=2)}

Identify the root cause with evidence."""

        response = await self.llm.chat.completions.create(
            model="gpt-4o",
            messages=[
                {"role": "system", "content": self.system_prompt},
                {"role": "user", "content": diagnosis_prompt},
            ],
            response_format={"type": "json_object"},
            temperature=0.1,  # Low temperature for factual analysis
        )

        result = json.loads(response.choices[0].message.content)
        timeline.append({"ts": "now", "event": f"Diagnosis: {result['root_cause']}"})

        return DiagnosticResult(
            root_cause=result["root_cause"],
            confidence=result["confidence"],
            evidence=result["evidence"],
            suggested_remediation=result["suggested_remediation"],
            affected_services=result.get("affected_services", [service]),
            timeline=timeline,
        )

    async def _gather_logs(self, service: str) -> dict:
        """Gather and summarize error logs."""
        errors = await self.splunk.get_error_summary(service, minutes=15)
        recent = await self.splunk.search_logs(
            f'service="{service}" level=ERROR', earliest="-5m", max_results=20
        )
        return {"error_summary": errors, "recent_errors": recent}

    async def _gather_metrics(self, service: str) -> dict:
        """Gather key health metrics."""
        return await self.grafana.get_service_health(service)

3. Automated Remediation

Safe Remediation Patterns ▼

The Cardinal Rule

An agent that makes things worse is worse than no agent at all. Every remediation action must have: a dry-run mode, an approval gate (for high-severity), a blast-radius limit, and an automatic rollback trigger.

"""Remediation Agent with safety controls."""
from dataclasses import dataclass
from enum import Enum
from typing import Optional, Callable
import asyncio


class RiskLevel(Enum):
    LOW = "low"          # Read-only, info gathering
    MEDIUM = "medium"    # Restart pods, clear cache
    HIGH = "high"        # Scale infra, modify config
    CRITICAL = "critical"  # Rollback deployment, failover


class ApprovalStatus(Enum):
    PENDING = "pending"
    APPROVED = "approved"
    DENIED = "denied"
    TIMED_OUT = "timed_out"
    AUTO_APPROVED = "auto_approved"


@dataclass
class RemediationAction:
    name: str
    description: str
    risk_level: RiskLevel
    execute_fn: Callable
    rollback_fn: Optional[Callable] = None
    dry_run_fn: Optional[Callable] = None
    blast_radius: str = "single-pod"  # single-pod, single-service, multi-service, cluster


class RemediationAgent:
    """Executes remediation actions with safety controls."""

    APPROVAL_REQUIRED = {RiskLevel.HIGH, RiskLevel.CRITICAL}
    AUTO_APPROVE_TIMEOUT = 300  # 5 minutes

    def __init__(self, approval_service, audit_logger, circuit_breaker):
        self.approval = approval_service
        self.audit = audit_logger
        self.circuit_breaker = circuit_breaker

    async def execute(self, action: RemediationAction, incident_id: str,
                      diagnosis: 'DiagnosticResult') -> dict:
        """Execute a remediation action with full safety pipeline."""

        # Step 0: Circuit breaker check
        if not self.circuit_breaker.is_healthy(action.name):
            self.audit.log(incident_id, "blocked", f"Circuit breaker open for {action.name}")
            return {"status": "blocked", "reason": "circuit_breaker_open"}

        # Step 1: Dry run
        if action.dry_run_fn:
            dry_result = await action.dry_run_fn()
            self.audit.log(incident_id, "dry_run", str(dry_result))
            if dry_result.get("would_fail"):
                return {"status": "aborted", "reason": "dry_run_failed", "detail": dry_result}

        # Step 2: Approval gate
        if action.risk_level in self.APPROVAL_REQUIRED:
            approval = await self._request_approval(action, incident_id, diagnosis)
            if approval != ApprovalStatus.APPROVED:
                self.audit.log(incident_id, "approval_denied", approval.value)
                return {"status": "approval_denied", "approval": approval.value}

        # Step 3: Execute with monitoring
        self.audit.log(incident_id, "executing", action.description)
        try:
            result = await asyncio.wait_for(action.execute_fn(), timeout=60.0)
            self.audit.log(incident_id, "executed", str(result))

            # Step 4: Verify remediation worked
            verification = await self._verify_remediation(action, incident_id)
            if not verification["healthy"]:
                # Auto-rollback if verification fails
                if action.rollback_fn:
                    self.audit.log(incident_id, "rolling_back", "Verification failed")
                    await action.rollback_fn()
                    self.circuit_breaker.record_failure(action.name)
                    return {"status": "rolled_back", "reason": "verification_failed"}

            self.circuit_breaker.record_success(action.name)
            return {"status": "success", "result": result, "verification": verification}

        except asyncio.TimeoutError:
            self.audit.log(incident_id, "timeout", f"{action.name} timed out after 60s")
            self.circuit_breaker.record_failure(action.name)
            return {"status": "timeout"}

        except Exception as e:
            self.audit.log(incident_id, "error", str(e))
            self.circuit_breaker.record_failure(action.name)
            if action.rollback_fn:
                await action.rollback_fn()
            return {"status": "error", "error": str(e)}

    async def _request_approval(self, action, incident_id, diagnosis) -> ApprovalStatus:
        """Request human approval for high-risk actions."""
        request = {
            "incident_id": incident_id,
            "action": action.name,
            "risk_level": action.risk_level.value,
            "blast_radius": action.blast_radius,
            "description": action.description,
            "diagnosis_confidence": diagnosis.confidence,
            "root_cause": diagnosis.root_cause,
        }
        return await self.approval.request(request, timeout=self.AUTO_APPROVE_TIMEOUT)

    async def _verify_remediation(self, action, incident_id) -> dict:
        """Check if remediation resolved the issue (wait, then re-check metrics)."""
        await asyncio.sleep(30)  # Wait 30s for metrics to settle
        # Re-check the health metrics that triggered the alert
        return {"healthy": True, "check": "metrics_improved"}

4. Change Orchestration

Approval Workflows & Staged Rollouts ▼

Risk-Based Approval Routing

flowchart TD Action[Agent Proposes Action] --> Risk{Risk Assessment} Risk -->|LOW: read-only| Auto[Auto-Execute] Risk -->|MEDIUM: restart/scale| Team[Team Lead Approval] Risk -->|HIGH: rollback/config| Manager[Manager + SRE Lead] Risk -->|CRITICAL: failover| VP[VP Approval + War Room] Team -->|Approved| Canary[Canary Deploy 5%] Manager -->|Approved| Canary VP -->|Approved| Canary Canary --> Monitor{Monitor 5 min} Monitor -->|Healthy| Expand[Expand to 25%] Monitor -->|Degraded| Rollback[Auto-Rollback] Expand --> Monitor2{Monitor 5 min} Monitor2 -->|Healthy| Full[Full Rollout] Monitor2 -->|Degraded| Rollback 
"""Change orchestration with staged rollout."""


class ChangeOrchestrator:
    """Manages staged rollout of agent-initiated changes."""

    STAGES = [
        {"name": "canary", "percentage": 5, "duration_sec": 300},
        {"name": "partial", "percentage": 25, "duration_sec": 300},
        {"name": "majority", "percentage": 75, "duration_sec": 180},
        {"name": "full", "percentage": 100, "duration_sec": 0},
    ]

    def __init__(self, deployer, monitor, audit_logger):
        self.deployer = deployer
        self.monitor = monitor
        self.audit = audit_logger

    async def staged_rollout(self, change: dict, incident_id: str) -> dict:
        """Execute a change through progressive stages with automatic rollback."""
        baseline_metrics = await self.monitor.snapshot(change["service"])

        for stage in self.STAGES:
            self.audit.log(incident_id, "stage_start",
                           f"{stage['name']}: {stage['percentage']}%")

            # Apply change to percentage of traffic/pods
            await self.deployer.apply(change, percentage=stage["percentage"])

            if stage["duration_sec"] == 0:
                break  # Final stage, no monitoring needed

            # Monitor for degradation
            degraded = await self._monitor_stage(
                change["service"], baseline_metrics, stage["duration_sec"]
            )

            if degraded:
                self.audit.log(incident_id, "rollback",
                               f"Degradation detected at {stage['name']} stage")
                await self.deployer.rollback(change)
                return {
                    "status": "rolled_back",
                    "failed_stage": stage["name"],
                    "reason": degraded,
                }

            self.audit.log(incident_id, "stage_passed", stage["name"])

        return {"status": "completed", "stages_passed": len(self.STAGES)}

    async def _monitor_stage(self, service: str, baseline: dict,
                              duration_sec: int) -> Optional[str]:
        """Monitor service health during a rollout stage."""
        check_interval = 30  # Check every 30 seconds
        checks = duration_sec // check_interval

        for _ in range(checks):
            await asyncio.sleep(check_interval)
            current = await self.monitor.snapshot(service)

            # Compare against baseline with thresholds
            if current["error_rate"] > baseline["error_rate"] * 2:
                return f"Error rate doubled: {current['error_rate']:.2%} vs baseline {baseline['error_rate']:.2%}"
            if current["latency_p99"] > baseline["latency_p99"] * 1.5:
                return f"P99 latency 1.5x: {current['latency_p99']:.0f}ms vs baseline {baseline['latency_p99']:.0f}ms"

        return None  # No degradation detected

class IncidentSummarizer:

            ],
            temperature=0.2,
        )

7. Production Considerations

Making It Real: What Breaks in Production ▼

Failure Modes and Mitigations

Failure Mode Impact Mitigation
LLM provider is down Agent can't diagnose Rule-based fallback: pattern matching on known incident types. Route to human immediately.
Wrong diagnosis Wrong remediation applied Confidence threshold (block < 0.6). Staged rollout catches bad fixes. Auto-rollback on degradation.
Remediation makes it worse Extended outage Canary stage catches this. Auto-rollback if metrics degrade. Circuit breaker disables that remediation type.
Circular alerts Agent action triggers new alert → agent loops Dedup window: ignore alerts for same service within 10 min of agent action. Max actions per incident.
Splunk/Grafana timeout Incomplete investigation Proceed with partial data + lower confidence. Note which data sources failed in the diagnosis.

The Agent Must Be More Reliable Than What It Monitors

  • Separate infrastructure: Agent platform runs on different cluster/cloud than production services
  • No shared dependencies: If the database is down, the agent shouldn't also be down
  • Graceful degradation: If AI is unavailable, system should still function as a dashboard/alert router
  • Self-monitoring: The agent platform has its own health checks and alerts (monitored by humans, not by itself)

8. Interview Prep

Common Interview Questions ▼

"How would you design an AI agent that can safely restart production services?"

What they're looking for: Safety-first thinking. You should discuss: scoped permissions (agent can only restart specific services), dry-run mode, approval gates for high-risk actions, staged rollout (canary first), automatic rollback on degradation, circuit breaker to disable agent if too many failures, and immutable audit trail.

Red flag: Jumping straight to the LLM prompt without discussing safety controls.

"How do you ensure an AI diagnostic agent gives the right root cause?"

Key points: Confidence scoring with thresholds, evidence-based diagnosis (cite specific logs/metrics), validation against known patterns, human escalation when confidence is low, feedback loop from resolution outcomes to improve future diagnoses.

"What happens when the LLM hallucinates during incident response?"

Answer framework: Multiple defense layers: (1) structured output validation (JSON schema), (2) evidence verification (does the cited log line actually exist?), (3) confidence thresholds, (4) staged execution (wrong diagnosis caught during canary), (5) deterministic fallback for known patterns, (6) human-in-the-loop for anything above medium risk.

"How do you handle the chicken-and-egg problem of the agent platform itself having an outage?"

Answer: Infrastructure separation (different cluster/region), no shared dependencies with monitored services, graceful degradation to manual workflow, self-monitoring with human-only alerting for the agent platform itself. The agent platform should have a higher availability SLO than any service it monitors.

9. Flashcard Suggestions

Q: What are the four safety controls every agent remediation action must have?
A: (1) Dry-run mode to test without executing, (2) Approval gate for high-risk actions, (3) Blast-radius limit (scope to single service/pod), (4) Automatic rollback trigger if metrics degrade after execution.
Q: What is a circular alert and how do you prevent it?
A: When an agent's remediation action triggers a new alert, which triggers the agent again, creating an infinite loop. Prevent with: dedup window (ignore alerts for same service within N minutes of agent action), max actions per incident limit, and circuit breaker on repeated failures.
Q: Why must the agent platform be on separate infrastructure from monitored services?
A: If they share infrastructure, the same failure that triggers the alert can also take down the agent. Example: if a database outage causes the incident and the agent's state store is on the same database, the agent can't function. The agent must be more reliable than what it monitors.
Q: What is the SLO budget breakdown for an agent diagnostic pipeline?
A: Triage: 3s (small model, cached patterns). Data gathering: 5s (parallel tool calls). Diagnosis: 10s (streaming, semantic cache). Remediation plan: 5s (template + LLM fill). Total: 30s SLO with 7s buffer for retries.
Q: What determines whether an agent action needs human approval?
A: Risk level and blast radius. LOW risk (read-only): auto-execute. MEDIUM (restart pods, clear cache): team lead approval. HIGH (rollback deployment, config change): manager + SRE lead. CRITICAL (failover, data migration): VP approval + war room. Also consider diagnosis confidence: if < 0.85, escalate regardless of risk level.

10. Quiz

1. An agent diagnoses a memory leak with 0.72 confidence and proposes a rolling restart (MEDIUM risk). Should it auto-execute?

Answer: It depends on your confidence threshold policy. With 0.72 confidence, most production systems would require human review (typical auto-execute threshold is 0.85). Even though MEDIUM risk normally allows team-lead approval, the low confidence should escalate the decision. Best practice: present the diagnosis and proposed action to the on-call engineer with the evidence, let them decide.

2. Your agent successfully restarts pods to fix an OOM issue, but the same alert fires again 20 minutes later. What went wrong and what should the agent do?

Answer: The restart treated the symptom (OOM), not the root cause (memory leak). The agent should: (1) recognize this is a recurring pattern (same alert, same service, recent remediation), (2) escalate to a different remediation strategy (rollback deployment instead of restart), (3) if it already tried rollback, escalate to human with full context. The circuit breaker should track that "restart_pods" failed for this service, preventing the same ineffective action.

3. During a canary rollback at 5%, you notice error rate dropped for the canary pods but overall service error rate is unchanged. Why?

Answer: The remaining 95% of pods are still on the bad version. The canary result is actually positive — it confirms the rollback helps. The staged rollout should proceed to the next stage (25%). If at 25% the overall error rate starts dropping proportionally, that's strong confirmation. If overall metrics don't improve even at 25%, the root cause may not be the deployment.

4. Why should you use parallel tool calls for data gathering instead of sequential?

Answer: Under a 30s SLO, sequential calls to Splunk (2s) + Grafana (1.5s) + CMDB (0.5s) = 4s. In parallel: max(2s, 1.5s, 0.5s) = 2s. This saves 2s which is meaningful when every second counts during a P1 incident. Additionally, if one source times out, you still have data from the others (partial results are better than no results).

5. Name three things an immutable audit trail for agent actions should capture.

Answer: (1) The triggering alert/event with full context. (2) Every LLM prompt and response (what the agent "thought"). (3) Every tool call with inputs and outputs (what data the agent saw). (4) The diagnosis with confidence score and evidence. (5) The approval request and response (who approved, when). (6) The action executed and its result. (7) Verification metrics before and after. This enables full reconstruction of agent decision-making for compliance and post-incident review.
